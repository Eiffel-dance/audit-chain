# Audit Chain

A dependency-free Python reference implementation for security, audit, transaction-graph.

Run with: python3 demo.py
Tests: python3 -m unittest discover -s tests -v

## Scope

实现按租户分区的追加审计日志：每条记录包含租户、顺序号、事件和前一条摘要，读取方可以离线校验完整历史并定位第一个损坏的位置。追加必须拒绝错误的前序状态，校验结果要明确区分缺失、顺序错误和摘要错误；日志格式保持可迁移，不依赖网络服务或远端锚定。

租户身份按稳定的 JSON 数据身份划分（`json.dumps(..., sort_keys=True)`）：对象键顺序不影响身份，而 `1`、`1.0`、`true`、`"1"` 是四个互不相干的租户；append、verify、verify_all 共用同一套分区语义。

输入与读取都遵循标准 JSON 边界：append 的 tenant 和 event 只能由 null、布尔值、有限整数/浮点数、字符串、数组和键为字符串的对象递归组成，NaN、Infinity、-Infinity、非字符串键及无法无歧义编码的值一律抛出 `ValueError`（先于任何追加动作，不写入任何字节）。verify 的 tenant 参数采用同一定义：非法值在读取历史或触碰路径之前抛出 `ValueError`（不泄露 TypeError/RecursionError 或 JSON 编码异常），已损坏的文件与非法 tenant 同时出现时同样是 `ValueError` 优先且字节不变；合法 tenant 的校验结果（missing/sequence/digest 及 expected_count 语义）保持不变。verify/verify_all 以同一规则解释历史：包含重复对象键、NaN/Infinity/-Infinity 或其他非标准 JSON 内容的物理行按 missing 类损坏处理并停在首次出现处。

同一路径可被多个线程或进程同时读写而仍保持单一可验证历史：append 在整个"读取最新状态—计算 seq/prev/hash—追加"区间持有排他文件锁（`flock`，无第三方依赖），因此每条记录都基于其真正落盘前的最新完整状态计算，任何调用都不会覆盖既有字节；verify/verify_all 持共享锁读取，只会看到某次追加之前或之后完整自洽的文件视图，绝不会把写了一半的记录报成损坏。历史一旦损坏，并发 append 仍以相同的 tenant/seq/line/reason（missing、sequence、digest 之一）抛出 `AuditChainStateError` 且不改动文件。旧版 JSONL 文件格式不变，可继续直接验证。

`append_batch(tenant, events)` 一次提交一组同租户事件：events 必须是列表（空列表直接返回 `[]`，不创建文件、不改动字节；其他类型一律 `ValueError`），租户与列表中每个事件沿用与 append 相同的标准 JSON 边界。成功时按输入顺序分配连续 seq——首条接在该租户当前链末（prev 为提交前最后一条记录的摘要），后续逐条引用批次内前一条摘要——并在同一次排他租约内以一个字节块整体追加，因此整批对其他追加/校验是一个不可分割的可见结果：同租户追加只能整体落在批前或批后，不同租户仍可交错且各自从 1 计数。落盘为每行一个 JSON 对象，与逐条调用 append 产生的字节和 verify/verify_all 计数、摘要、首个错误位置完全一致；扫描到与 append 相同的首个损坏点时抛出同样字段（tenant、seq、reason、line）的 `AuditChainStateError`，失败不留任何部分记录。

`append_if_head(tenant, event, expected_count, expected_hash)` 是带前序断言的单条条件追加：调用方给出链头应有的记录数和末条摘要，只有二者与租约内实际读到的链头**同时**相等时才追加下一条。`expected_count` 必须是非负普通整数（`bool`、负数、浮点、字符串、`None` 及其他类型一律 `ValueError`），`expected_hash` 必须恰好是 64 个小写十六进制字符（长度不符、大写、非 hex 字符或非字符串一律 `ValueError`），空链的期望摘要使用现有 `ZERO`。tenant、event 继续沿用与 append 完全相同的标准 JSON 边界；所有非法值（含布尔计数、负数计数、格式不正确的摘要）都在读取日志或创建文件之前以 `ValueError` 结束，不创建、不修改日志。成功时返回值与 append 完全相同（同一记录 dict、同样的五个字段、seq、prev 与摘要算法），落盘字节与对相同历史调用 append 逐字节一致。断言格式合法但与当前链头不符时抛出新增的 `AuditChainConflictError`，公开 `tenant`、`expected_count`、`expected_hash`、`actual_count`、`actual_hash` 五个字段，且 `reason` 固定为 `"conflict"`；`actual_count` 为零时 `actual_hash` 为 `ZERO`，历史为空（日志不存在、为空或只含其他租户记录）时按同一规则比较，失败调用不写入任何字节——对尚不存在的日志作出非空断言尤其不会创建日志文件。历史损坏时沿用 `AuditChainStateError`：tenant、seq、line、reason 语义与 append/verify/export 完全一致，reason 仍只取 missing、sequence、digest，错误优先级与文件字节不变，且状态错误优先于冲突判定（不会拿不可验证的链去比较断言）。校验、比较与写入在同一次排他租约内完成：日志已存在时使用与 append 相同的数据文件排他锁；日志尚不存在时，排他目录取锁（普通 append 创建文件时同样短暂持有该锁）覆盖"探测不存在—空链比较—创建文件"整段，且文件只在断言获胜后才被创建，加锁顺序始终是目录锁先于文件锁，不会与普通 append 死锁。因此并发提交同一个链头时至多一个成功，其余调用都在锁内观察到获胜者写入的新链头并得到确定的冲突异常（actual_* 反映获胜后的真实计数与末条摘要）。append、append_batch、verify、verify_all、verify_bytes、verify_all_bytes、export_tenant、read_tenant 的签名、结果、JSONL 格式、租户身份区分及离线行为保持不变。

`append_batch_if_head(tenant, events, expected_count, expected_hash)` 把批量追加与头部断言合并为一次原子提交：events 必须是列表（其他类型一律 `ValueError`；空列表在全部参数校验通过后直接返回 `[]`，不创建文件、不读写任何字节，头部断言不被求值），tenant 与每个事件沿用与 append 相同的标准 JSON 边界，`expected_count`/`expected_hash` 的边界与 append_if_head 完全一致（非负普通整数、拒绝 bool；恰好 64 个小写十六进制字符，空链用 `ZERO`），所有非法值都在读取历史或触碰路径之前统一抛 `ValueError`。events 非空时，扫描、比较与写入在同一次排他租约内完成：先以与 append 完全相同的规则校验该租户从第一条到链尾的完整链，再同时比较实际记录数与末条摘要，二者都匹配才追加。成功时返回按 seq 排列的记录 dict 列表（tenant、seq、event、prev、hash 五字段），首条 seq 为 `expected_count + 1`、prev 为 `expected_hash`，后续记录在批次内部连续链接，整批作为一个不可分割的字节区间一次落盘——其他租户的追加只能整体落在批前或批后，持共享锁的读取方只能看到提交前或提交后的完整快照；落盘字节与对同一链头逐条调用 append（或一次 append_batch）得到的历史逐字节一致。日志尚不存在时只有 `(0, ZERO)` 断言的非空批次可以创建文件，其余非空断言抛 `AuditChainConflictError`（actual 为 `(0, ZERO)`）且不创建文件；已存在日志上的头部不匹配同样抛 `AuditChainConflictError`，公开 `tenant`、`expected_count`、`expected_hash`、`actual_count`、`actual_hash`，`reason` 固定为 `"conflict"`。扫描发现缺失、顺序错误或摘要错误时优先抛 `AuditChainStateError`（tenant、seq、reason、物理行号语义与 append 一致，状态错误优先于冲突判定）；冲突与状态错误路径都不写入任何部分记录。并发调用共享同一链头时至多一个批次成功，其余调用在锁内观察到获胜批次之后的新链头并得到携带实际值的冲突异常。功能不依赖网络或远端锚定；append、append_batch、append_if_head、verify、verify_all、verify_bytes、verify_all_bytes、export_tenant、read_tenant 的签名、结果与异常边界保持不变。

`append_many(entries)` 是跨租户的原子追加入口：entries 必须是列表，每项必须是**恰好**含 `tenant`、`event` 两个键的对象（参数不是列表、成员不是对象、缺键、多键或键集合不符一律 `ValueError`；非字符串成员键同样拒绝），列表顺序就是记录的写入顺序。每个 tenant 与 event 沿用与 append 完全相同的标准 JSON 边界；列表形状、成员形状、键集合以及全部 tenant/event 在触碰路径、读取历史或加锁之前完成校验，任何边界错误都统一为 `ValueError` 且不创建文件、不读写字节（即使目标日志已损坏也不读取）。空列表在参数校验通过后直接返回 `[]`：不创建、不读取也不改变日志。非空调用在一次排他租约内读取一致快照，对本次涉及的每个租户执行与 append 完全相同的完整链扫描——序号从 1 起连续、prev 与当前链头衔接、每条 hash 可重算——缺失/无法解析为 `missing`、顺序错误为 `sequence`、prev 或 hash 不一致为 `digest`，抛出字段（tenant、seq、reason、物理行号）与 append 完全一致的 `AuditChainStateError`；多个受影响链同时有问题时，按日志中首次出现的物理行确定结果，物理行相同再按输入的首次出现顺序确定；任何校验失败都不写入部分记录、字节保持不变，未涉及租户自身的损坏不阻止本次提交。全部前序状态有效后，同一租户在列表中可出现多次，其记录按出现顺序连续编号（首条接该租户提交前的链尾，后续逐条引用本组内前一条摘要），其他租户各自从当前链尾继续；返回与输入一一对应的记录 dict 列表，每项保留 tenant、seq、event、prev、hash 五个字段，物理 JSONL 顺序与输入顺序一致，摘要与前序摘要规则、序列化（`sort_keys=True`、`allow_nan=False`）与换行补全规则与 append 完全相同——落盘字节与按输入顺序逐条调用 append 逐字节一致。全部生成记录作为一个不可分割的追加区块一次写入：持共享锁的并发读取只能看到提交前或提交后的完整快照，竞争写入在同一租约上串行、整体落在区块之前或之后且不会覆盖既有字节，其他租户的合法交错记录继续保留；目标文件不存在时仅在校验成功后才创建。生成的日志可由现有 verify、verify_all、verify_bytes、verify_all_bytes、read_tenant、export_tenant 与离线字节校验直接验证，import_tenant 的既有空链冲突语义保持不变。功能不依赖网络或远端锚定；JSONL 字段、租户身份区分、摘要算法、错误类型与既有入口的签名、返回值及行为保持兼容。

`append_many_if_heads(entries)` 把跨租户原子追加与每租户链头断言合并为一次离线原子提交，相当于 `append_many` 的不可分割分组提交与每租户一个 `append_batch_if_head` 式头部断言的融合：entries 必须是列表，每项必须是**恰好**含 `tenant`、`events`、`expected_count`、`expected_hash` 四个键的对象（参数不是列表、成员不是对象、缺键、多键或键集合不符一律 `ValueError`；非字符串成员键同样拒绝）；events 必须是非空列表（非列表或空列表一律 `ValueError`——空 `entries` 列表才是校验通过后的空操作），其每个事件沿用与 append 完全相同的标准 JSON 边界；`expected_count` 必须是非负普通整数（`bool` 即使是 int 子类也拒绝，负数、浮点、字符串、`None` 及其他类型一律 `ValueError`），`expected_hash` 必须恰好是 64 个小写十六进制字符（长度不符、大写、非 hex 字符或非字符串一律 `ValueError`），空链断言使用现有 `ZERO`；同一规范 JSON 身份的 tenant 在整个 entries 中至多出现一次，重复（含仅对象键顺序不同但身份相同）一律 `ValueError`，而 `1`、`1.0`、`true`、`"1"` 等不同 JSON 身份仍是互不相关的租户。列表形状、成员形状、键集合、events 非空、计数/摘要格式、租户唯一性以及全部 tenant/event 的标准 JSON 边界都在加锁、探测路径或读取任何字节之前完成，任何非法输入统一抛 `ValueError` 且不创建文件、不读写字节，即使目标日志已损坏也不读取。空列表在全部校验通过后直接返回 `[]`：不创建、不读取也不改变日志，头部断言不被求值。非空调用在一次排他租约内读取一致快照，只对本次涉及的每个租户执行与 append 完全相同的完整链扫描——只验证涉及租户从 seq=1 到链尾的顺序、prev 与每条 hash，缺失或无法解析为 `missing`、序号错误为 `sequence`、前序或当前摘要不符为 `digest`，并以 `AuditChainStateError` 的 tenant、seq、line、reason 字段报告；多个涉及链同时损坏时按物理行号优先、输入首次出现顺序打破平局（与 append_many 完全一致），未涉及租户的损坏忽略。任何状态错误都不拿不可验证的链去比较断言、不写入任何字节。涉及链状态全部有效后，按 entries 顺序依次比较每个断言的计数与末条摘要，首个不符项（无论租户）按 entries 顺序抛 `AuditChainConflictError`，公开该租户的 `expected_count`、`expected_hash`、`actual_count`、`actual_hash`，`reason` 固定为 `"conflict"`，`actual_count` 为零时 `actual_hash` 为 `ZERO`；状态错误严格优先于冲突，冲突路径同样不写入任何字节。日志不存在时，只有**全部**断言都是 `(0, ZERO)` 才能创建文件；否则按 entries 顺序首个非空/错摘要断言在目录租约内确定性地抛出 actual 为 `(0, ZERO)` 的冲突，且不创建任何文件。全部断言匹配时，按 entries 顺序、每个 entry 内按 events 顺序生成并返回五字段记录（tenant、seq、event、prev、hash）列表：每个租户从其断言链尾（首条 prev 为 `expected_hash`）连续编号，同一 entry 的多条事件在批次内连续链接，字段、摘要算法、规范化序列化（`sort_keys=True`、`allow_nan=False`）、末行缺换行时补换行及租户身份规则与 append_batch、append_many 完全一致，落盘字节与对相同链头按相同 entry/event 顺序逐条调用 append 逐字节一致；所有记录作为不可分割 JSONL 区块一次追加，其他租户的合法交错记录继续保留。并发提交在同一排他租约上串行：竞争相同/相交链头的调用至多一个成功，其余在锁内观察到获胜者写入后的新链头并得到携带获胜后实际计数与末条摘要的确定冲突，持共享锁的读取方只能看到提交前或提交后的完整快照，绝不会看到半个区块。生成的日志可由 append、append_batch、append_if_head、append_batch_if_head、append_many、verify、verify_all、verify_bytes、verify_all_bytes、read_tenant、export_tenant/import_tenant 直接继续追加、校验、分页读取与离线迁移；功能不依赖网络或远端锚定，既有入口的签名、返回值、异常字段与可迁移 JSONL 格式保持兼容。

`export_tenant(tenant)` 面向离线迁移，按租户导出单链：返回 UTF-8 编码的 `bytes`，本身不创建、不改写、不删除任何文件，也不访问网络；调用方自行把返回字节写入新的 JSONL 路径后，新的 `AuditChain` 可直接用现有 verify/verify_all 离线验证。tenant 采用与 append/verify 完全相同的标准 JSON 边界，非法值在读取任何历史之前统一抛 `ValueError` 且不读取、不创建文件。导出在单次只读共享锁快照中完成：先运行与 `verify(tenant)` 相同的完整扫描，整份快照对该租户有效后才开始拼装结果，因此源状态错误统一抛 `AuditChainStateError`（填入目标 tenant、首个应检查的 seq、reason 与物理行号），绝不会先返回已收集的前缀；reason 仅为 missing、sequence、digest，优先级与行号沿用现有校验规则。源文件不存在或为空是合法空快照，成功返回 `b""`。导出内容只包含目标租户在源文件中按物理顺序出现的记录（其他租户的交错记录被丢弃且不导致重排），每行一个 JSON 对象，沿用 append 的序列化（`sort_keys=True`、`allow_nan=False`）与换行规则，字段、值、seq、prev、hash 与源历史语义一致；JSON 身份不同的租户（如 `1`、`1.0`、`true`、`"1"`）各自独立导出、互不混入。快照未变更时重复调用得到字节完全相同的结果；并发追加期间，导出只能观察到某次追加之前或之后的完整快照，失败时不写入任何字节。

`import_tenant(tenant, data)` 是 `export_tenant` 的离线反向入口：把一段单租户 JSONL 历史（通常来自另一条日志的导出字节）整体移植/灾备恢复到本日志，全程不依赖网络或远端锚定。调用先于任何历史读取、路径探测和加锁完成参数边界校验：tenant 沿用与 append/verify/export 完全相同的标准 JSON 边界（NaN/Infinity、非字符串键、循环容器及无标准 JSON 编码的值一律 `ValueError`），`data` 必须是 `bytes`（`str`、`bytearray` 及其他类型一律 `ValueError`），参数边界错误优先于一切历史状态处理，且不创建文件、不改字节。`data` 为空 `b""` 时在校验通过后直接返回 `[]`：不创建文件、不读取历史、不改变任何字节（即使目标日志已损坏也不读取）。非空 `data` 必须是严格 UTF-8、每行一个标准 JSON 对象的单租户历史；在触碰目标之前先完整校验整条输入链——从 `seq=1`、`prev=ZERO` 起逐行确认必需字段、连续顺序与摘要：解析失败、重复键、非标准数字、非法 UTF-8 或缺字段抛 `AuditChainStateError`、reason 为 `missing`，顺序错误为 `sequence`，prev 或 hash 不一致为 `digest`，并准确填充 tenant、seq 与物理行号（行号与优先级规则与 append/verify/export 完全一致）；混入任何其他规范 JSON 身份的租户记录（含交错的其他租户、`1` 与 `"1"` 这类不同身份）违反单租户输入契约，统一抛 `ValueError`。随后在同一次受保护操作（与 append 相同的数据文件排他租约；目标不存在时经目录租约原子创建）内校验目标文件：目标租户已有任何记录即抛 `AuditChainConflictError`，固定 `expected_count=0`、`expected_hash=ZERO`，`actual_count`/`actual_hash` 反映租约内观察到的目标尾部（含其他租户交错后的该租户真实尾摘要）；目标历史损坏时优先返回与 append 完全相同的 `AuditChainStateError`（状态错误优先于冲突判定），其他租户自身的摘要损坏不影响导入。任何失败路径都不写入部分记录、不改变既有字节。成功时把整段历史作为一个不可分割的字节块一次追加（目标最后一行缺换行时沿用 append 的补换行规则），记录原有的 tenant、seq、event、prev、hash 原样保留——既不重编号也不重算摘要，首条仍以 `ZERO` 为锚；返回按 seq 排列的记录 dict 列表（恰含五个现有字段及其输入原值）。目标文件可已包含其他租户的有效交错记录，导入后 verify、verify_all、verify_bytes、verify_all_bytes、export_tenant、read_tenant 均按现有规则通过，且该租户可直接用 append/append_if_head 从导入尾部继续；JSON 身份不同的租户互不可见、互不冲突。并发导入/追加同租户时，写操作在同一排他租约上串行：至多一次导入成功提交完整区块，其余调用要么观察到该租户非空链头而得到携带实际尾部的冲突，要么在导入之前成功并让随后的导入冲突；共享锁读取方只能看到整段导入之前或之后的完整快照。append、append_batch、append_if_head、append_batch_if_head、verify、verify_all、verify_bytes、verify_all_bytes、export_tenant、read_tenant 的签名、返回值、异常字段、租户身份区分、并发快照与 JSONL 可迁移格式保持不变。

`read_tenant(tenant, start_seq=1, page_size=None)` 是只读的按租户分页读取入口：返回按该租户 `seq` 升序排列的记录列表，每项保留 tenant、seq、event、prev、hash 五个现有字段及其磁盘原值；列表只包含目标租户，其他租户的交错记录既不出现也不改变分页顺序（分页只按目标租户自己的 1..count 计数）。`start_seq` 必须是大于等于 1 的普通整数（拒绝 bool、浮点及其他类型），缺省 1 表示从第一条开始；`page_size` 必须是正的普通整数或 `None`，`None`（缺省）表示读到链尾。起始序号超过当前条数、或末页不足 page_size 都不是错误：返回相应后缀，可能为 `[]`。tenant、start_seq、page_size 在读取任何历史之前全部校验——tenant 沿用与 append/verify/export 相同的标准 JSON 边界，NaN、Infinity、-Infinity、非字符串对象键、循环容器及布尔/其他非标准值统一抛 `ValueError`，非法分页参数同样抛 `ValueError`，且不创建、不修改任何文件。读取在单次只读共享锁快照中完成（与 verify/export 相同）：先以与 `verify(tenant)` 完全相同的 JSON 身份与摘要规则扫描该租户从第一条到链尾的完整历史，整份快照对该租户有效后才在内存中截取所请求页；因此并发追加只能让本次结果对应某次追加之前或之后的完整快照，绝不会出现撕裂页，且即使请求页位于损坏点之前，缺字段、非法 UTF-8 或 JSON、序号不连续、前序摘要不匹配或当前摘要重算不一致都会使整个调用抛出 `AuditChainStateError` 而绝不返回已验证前缀，定位字段（tenant、seq、reason、line）与 verify/append/export_tenant 完全一致，reason 仅为 missing、sequence、digest 并优先报告首次发现的位置。目标租户不存在或日志不存在视为空链，成功返回 `[]`。该入口不写分页缓存、不改动原始字节、不依赖网络；append、append_batch、verify、verify_all、verify_bytes、verify_all_bytes、export_tenant 的签名、返回值、异常边界、并发一致性及可迁移日志格式保持不变。

`verify_bytes(data, tenant, expected_count=None)` 与 `verify_all_bytes(data)` 是纯内存离线校验入口：调用方把 JSONL 历史的原始 `bytes` 直接传入（`export_tenant` 导出的单租户字节，或包含交错租户的完整日志均可），入口绝不读取、创建或修改构造器所指向的路径，也不依赖网络、远端锚定或其他服务；结果只依据传入快照，调用期间不修改 `data`。两个入口复用与 verify/verify_all 完全相同的 JSON 标准化、租户身份与摘要算法逐行校验，因此返回结构、reason 分类（missing/sequence/digest）、`at` 口径、租户首次出现顺序与计数与文件入口逐字节一致；空 `bytes` 是成功的空历史（`verify_bytes` 返回 `{"ok": True, "count": 0}`，`verify_all_bytes` 返回 `{"ok": True, "tenants": []}`），且不创建任何文件。空行、非对象、缺字段、重复键、非标准数字（NaN/Infinity/溢出数）、非法 UTF-8 或 JSON 解析失败一律按 missing 处理，能定位的物理行使用行号；seq 不连续为 sequence，prev 或 hash 不符为 digest；其他租户的坏行同样会被发现，且更早的错误优先。`verify_bytes` 的 expected_count 短缺报 missing、超额报 sequence，与 verify 同口径；`data` 不是 `bytes`（含 `bytearray`/`str` 等）、tenant 越过标准 JSON 边界（NaN/Infinity、非字符串键、循环容器等），或 expected_count 不是 `None` 以外的非负整数（`bool` 同样拒绝）时，在任何解析之前抛出 `ValueError`，不泄漏底层解析异常。export_tenant 生成的字节写回另一个 `AuditChain` 后，文件校验与内存校验得到相同的摘要和计数。append、append_batch、verify、verify_all、export_tenant 的签名、格式、错误类型、并发快照及损坏前序拒绝行为保持不变。
