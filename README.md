# Audit Chain

A dependency-free Python reference implementation for security, audit, transaction-graph.

Run with: python3 demo.py
Tests: python3 -m unittest discover -s tests -v

## Scope

实现按租户分区的追加审计日志：每条记录包含租户、顺序号、事件和前一条摘要，读取方可以离线校验完整历史并定位第一个损坏的位置。追加必须拒绝错误的前序状态，校验结果要明确区分缺失、顺序错误和摘要错误；日志格式保持可迁移，不依赖网络服务或远端锚定。

租户身份按稳定的 JSON 数据身份划分（`json.dumps(..., sort_keys=True)`）：对象键顺序不影响身份，而 `1`、`1.0`、`true`、`"1"` 是四个互不相干的租户；append、verify、verify_all 共用同一套分区语义。

输入与读取都遵循标准 JSON 边界：append 的 tenant 和 event 只能由 null、布尔值、有限整数/浮点数、字符串、数组和键为字符串的对象递归组成，NaN、Infinity、-Infinity、非字符串键及无法无歧义编码的值一律抛出 `ValueError`（先于任何追加动作，不写入任何字节）。verify 的 tenant 参数采用同一定义：非法值在读取历史或触碰路径之前抛出 `ValueError`（不泄露 TypeError/RecursionError 或 JSON 编码异常），已损坏的文件与非法 tenant 同时出现时同样是 `ValueError` 优先且字节不变；合法 tenant 的校验结果（missing/sequence/digest 及 expected_count 语义）保持不变。verify/verify_all 以同一规则解释历史：包含重复对象键、NaN/Infinity/-Infinity 或其他非标准 JSON 内容的物理行按 missing 类损坏处理并停在首次出现处。

物理行边界只有字节 `0x0A`（LF）：一条记录仅由 LF 结束，紧邻其前的 `0x0D`（CRLF）不另起一行——行尾 CR 留在该行末尾，作为 JSON 行尾空白被严格解析接受。U+0085（NEL）、U+2028（行分隔符）、U+2029（段分隔符）和裸 CR 都**不是**行边界：前三个 Unicode 字符是当前行的合法 UTF-8 内容，即使在 JSON 字符串中以原始（未转义）UTF-8 出现——无论位于租户值、event 字符串、对象键、数组还是嵌套值中——整行仍只产生一个对象，租户身份、序号链与摘要链沿用既有规则；裸 CR 在 JSON 字符串内部为非法原始控制字符、在两个结构之间或结构之外同样使该行无法严格解析，统一按 missing 处理。实现从不使用 `str.splitlines()`（它会把上述字符都误判为行界），文件快照、`verify_bytes`、`verify_all_bytes`、分块校验、append/append_batch/条件追加、各类 import/export、`read_tenant`、`head`/`heads` 等所有读取 JSONL 的入口共用同一条 LF 物理行边界；纯校验结果的 `line`/`at` 一律按 LF 物理行计数（`verify_bytes` 的 `at` 继续是所定位的期望序号，文件/导入异常的 `line` 是物理行号）。有效 LF/CRLF 输入的结果字段、追加字节顺序、锁内完整快照与迁移格式保持兼容；规范化写入继续使用既有 JSON 序列化（默认 ASCII 转义，因此这些字符经 append 写入时为 `\u0085`/`\u2028`/`\u2029` 转义形式）并以单个 LF 结尾，`export_all` 对既有快照的原始字节（含原始分隔符与 CRLF）行为不变。文件读取或导入遇到无法严格解析的行、重复键、非标准数字或非法 UTF-8 时统一抛 `AuditChainStateError`、reason 固定 `missing`（纯校验入口继续返回既有失败结果），序号错误为 `sequence`，prev 或 hash 错误为 `digest`；任何失败都不追加、不创建文件、不写入部分导入内容。

同一路径可被多个线程或进程同时读写而仍保持单一可验证历史：append 在整个"读取最新状态—计算 seq/prev/hash—追加"区间持有排他文件锁（`flock`，无第三方依赖），因此每条记录都基于其真正落盘前的最新完整状态计算，任何调用都不会覆盖既有字节；verify/verify_all 持共享锁读取，只会看到某次追加之前或之后完整自洽的文件视图，绝不会把写了一半的记录报成损坏。历史一旦损坏，并发 append 仍以相同的 tenant/seq/line/reason（missing、sequence、digest 之一）抛出 `AuditChainStateError` 且不改动文件。旧版 JSONL 文件格式不变，可继续直接验证。

`append_batch(tenant, events)` 一次提交一组同租户事件：events 必须是列表（空列表直接返回 `[]`，不创建文件、不改动字节；其他类型一律 `ValueError`），租户与列表中每个事件沿用与 append 相同的标准 JSON 边界。成功时按输入顺序分配连续 seq——首条接在该租户当前链末（prev 为提交前最后一条记录的摘要），后续逐条引用批次内前一条摘要——并在同一次排他租约内以一个字节块整体追加，因此整批对其他追加/校验是一个不可分割的可见结果：同租户追加只能整体落在批前或批后，不同租户仍可交错且各自从 1 计数。落盘为每行一个 JSON 对象，与逐条调用 append 产生的字节和 verify/verify_all 计数、摘要、首个错误位置完全一致；扫描到与 append 相同的首个损坏点时抛出同样字段（tenant、seq、reason、line）的 `AuditChainStateError`，失败不留任何部分记录。

`append_batch_stream(tenant, events)` 是 append_batch 的**单次消费流式**入口：调用方把一次性事件可迭代对象（生成器、迭代器、元组、集合等）直接交给同租户原子追加，而不必先物化成列表。events 必须是可迭代对象，但**单个 `bytes`、`bytearray`、`str`、`dict` 都不是事件批次容器**（前两者迭代产出整数、str 产出字符、dict 只是一个事件对象），连同任何不可迭代值（`None`、布尔、数字及其他无 `__iter__` 的值）一律视为参数错误并抛 `ValueError`；普通列表本身也是可迭代对象，故同样可被接受。容器形状与 tenant 先于一切：迭代器只在 tenant 通过与 append 完全相同的标准 JSON 边界之后才被取得一次，且**只向前消费一次**，按产生顺序逐个校验每个 event 的标准 JSON 边界（非字符串对象键、循环容器、NaN/Infinity/-Infinity 等非有限数字及无法无歧义编码的值都在访问路径、探测文件或读取任何历史字节之前以 `ValueError` 结束，遇到首个非法 event 即停止索取后续元素）；迭代器在产生完毕前自己抛出的异常**原样透传**（不包装成 ValueError），此前已产生的前缀同样不会落盘。空迭代器在全部边界通过后直接返回 `[]`：**不创建、不读取也不改变日志**（即使历史已损坏也不扫描，且与一个已存在文件上的空操作一样不改动任何字节）。所有输入通过后，入口在**一次**与 append_batch 相同的排他数据文件租约内完成"读取该租户完整现状—构建—单块追加"：从 `seq=1`、`prev=ZERO` 起逐条检查该租户记录的字段、顺序、prev 与 hash（其他租户记录可自由交错并被跳过），并沿用 `AuditChainStateError` 的 tenant、seq、line、reason 字段定位**首次** missing、sequence 或 digest 损坏（规则与 append/append_batch 逐字段一致）；发现损坏时不比较、不写入，也不留下任何部分结果。状态有效时，按迭代顺序从该租户当前链尾分配连续 seq，首条 prev 使用租约内观察到的**实际末条摘要**（空链为 `ZERO`），后续记录依次链接批次内前一条摘要，返回与输入一一对应、恰含 tenant/seq/event/prev/hash 五字段的记录列表。序列化（`sort_keys=True`、`allow_nan=False`）、hash 计算与末行缺换行时补换行的规则和 append_batch **完全一致**，因此在同一历史上对相同事件序列，本入口生成并落盘的 JSONL 字节与 `append_batch` **逐字节相同**。整批记录作为一个不可分割的追加区块由一次块写入提交：竞争写入按完整批次前后排列（绝不插入批次两条记录之间），持共享锁的校验/读取只能看到提交前或提交后的完整历史；日志文件仅在成功调用时才创建，空迭代器保持无文件副作用，其他租户的物理交错顺序继续保留。新入口不联网、不引入远端锚定或任何额外落盘格式；现有追加、条件追加、跨租户追加、迁移、读取、校验、比较与清单入口的签名、结果、异常字段及 JSONL 兼容语义保持不变。

`append_if_head(tenant, event, expected_count, expected_hash)` 是带前序断言的单条条件追加：调用方给出链头应有的记录数和末条摘要，只有二者与租约内实际读到的链头**同时**相等时才追加下一条。`expected_count` 必须是非负普通整数（`bool`、负数、浮点、字符串、`None` 及其他类型一律 `ValueError`），`expected_hash` 必须恰好是 64 个小写十六进制字符（长度不符、大写、非 hex 字符或非字符串一律 `ValueError`），空链的期望摘要使用现有 `ZERO`。tenant、event 继续沿用与 append 完全相同的标准 JSON 边界；所有非法值（含布尔计数、负数计数、格式不正确的摘要）都在读取日志或创建文件之前以 `ValueError` 结束，不创建、不修改日志。成功时返回值与 append 完全相同（同一记录 dict、同样的五个字段、seq、prev 与摘要算法），落盘字节与对相同历史调用 append 逐字节一致。断言格式合法但与当前链头不符时抛出新增的 `AuditChainConflictError`，公开 `tenant`、`expected_count`、`expected_hash`、`actual_count`、`actual_hash` 五个字段，且 `reason` 固定为 `"conflict"`；`actual_count` 为零时 `actual_hash` 为 `ZERO`，历史为空（日志不存在、为空或只含其他租户记录）时按同一规则比较，失败调用不写入任何字节——对尚不存在的日志作出非空断言尤其不会创建日志文件。历史损坏时沿用 `AuditChainStateError`：tenant、seq、line、reason 语义与 append/verify/export 完全一致，reason 仍只取 missing、sequence、digest，错误优先级与文件字节不变，且状态错误优先于冲突判定（不会拿不可验证的链去比较断言）。校验、比较与写入在同一次排他租约内完成：日志已存在时使用与 append 相同的数据文件排他锁；日志尚不存在时，排他目录取锁（普通 append 创建文件时同样短暂持有该锁）覆盖"探测不存在—空链比较—创建文件"整段，且文件只在断言获胜后才被创建，加锁顺序始终是目录锁先于文件锁，不会与普通 append 死锁。因此并发提交同一个链头时至多一个成功，其余调用都在锁内观察到获胜者写入的新链头并得到确定的冲突异常（actual_* 反映获胜后的真实计数与末条摘要）。append、append_batch、verify、verify_all、verify_bytes、verify_all_bytes、export_tenant、read_tenant 的签名、结果、JSONL 格式、租户身份区分及离线行为保持不变。

`append_batch_if_head(tenant, events, expected_count, expected_hash)` 把批量追加与头部断言合并为一次原子提交：events 必须是列表（其他类型一律 `ValueError`；空列表在全部参数校验通过后直接返回 `[]`，不创建文件、不读写任何字节，头部断言不被求值），tenant 与每个事件沿用与 append 相同的标准 JSON 边界，`expected_count`/`expected_hash` 的边界与 append_if_head 完全一致（非负普通整数、拒绝 bool；恰好 64 个小写十六进制字符，空链用 `ZERO`），所有非法值都在读取历史或触碰路径之前统一抛 `ValueError`。events 非空时，扫描、比较与写入在同一次排他租约内完成：先以与 append 完全相同的规则校验该租户从第一条到链尾的完整链，再同时比较实际记录数与末条摘要，二者都匹配才追加。成功时返回按 seq 排列的记录 dict 列表（tenant、seq、event、prev、hash 五字段），首条 seq 为 `expected_count + 1`、prev 为 `expected_hash`，后续记录在批次内部连续链接，整批作为一个不可分割的字节区间一次落盘——其他租户的追加只能整体落在批前或批后，持共享锁的读取方只能看到提交前或提交后的完整快照；落盘字节与对同一链头逐条调用 append（或一次 append_batch）得到的历史逐字节一致。日志尚不存在时只有 `(0, ZERO)` 断言的非空批次可以创建文件，其余非空断言抛 `AuditChainConflictError`（actual 为 `(0, ZERO)`）且不创建文件；已存在日志上的头部不匹配同样抛 `AuditChainConflictError`，公开 `tenant`、`expected_count`、`expected_hash`、`actual_count`、`actual_hash`，`reason` 固定为 `"conflict"`。扫描发现缺失、顺序错误或摘要错误时优先抛 `AuditChainStateError`（tenant、seq、reason、物理行号语义与 append 一致，状态错误优先于冲突判定）；冲突与状态错误路径都不写入任何部分记录。并发调用共享同一链头时至多一个批次成功，其余调用在锁内观察到获胜批次之后的新链头并得到携带实际值的冲突异常。功能不依赖网络或远端锚定；append、append_batch、append_if_head、verify、verify_all、verify_bytes、verify_all_bytes、export_tenant、read_tenant 的签名、结果与异常边界保持不变。

`append_many(entries)` 是跨租户的原子追加入口：entries 必须是列表，每项必须是**恰好**含 `tenant`、`event` 两个键的对象（参数不是列表、成员不是对象、缺键、多键或键集合不符一律 `ValueError`；非字符串成员键同样拒绝），列表顺序就是记录的写入顺序。每个 tenant 与 event 沿用与 append 完全相同的标准 JSON 边界；列表形状、成员形状、键集合以及全部 tenant/event 在触碰路径、读取历史或加锁之前完成校验，任何边界错误都统一为 `ValueError` 且不创建文件、不读写字节（即使目标日志已损坏也不读取）。空列表在参数校验通过后直接返回 `[]`：不创建、不读取也不改变日志。非空调用在一次排他租约内读取一致快照，对本次涉及的每个租户执行与 append 完全相同的完整链扫描——序号从 1 起连续、prev 与当前链头衔接、每条 hash 可重算——缺失/无法解析为 `missing`、顺序错误为 `sequence`、prev 或 hash 不一致为 `digest`，抛出字段（tenant、seq、reason、物理行号）与 append 完全一致的 `AuditChainStateError`；多个受影响链同时有问题时，按日志中首次出现的物理行确定结果，物理行相同再按输入的首次出现顺序确定；任何校验失败都不写入部分记录、字节保持不变，未涉及租户自身的损坏不阻止本次提交。全部前序状态有效后，同一租户在列表中可出现多次，其记录按出现顺序连续编号（首条接该租户提交前的链尾，后续逐条引用本组内前一条摘要），其他租户各自从当前链尾继续；返回与输入一一对应的记录 dict 列表，每项保留 tenant、seq、event、prev、hash 五个字段，物理 JSONL 顺序与输入顺序一致，摘要与前序摘要规则、序列化（`sort_keys=True`、`allow_nan=False`）与换行补全规则与 append 完全相同——落盘字节与按输入顺序逐条调用 append 逐字节一致。全部生成记录作为一个不可分割的追加区块一次写入：持共享锁的并发读取只能看到提交前或提交后的完整快照，竞争写入在同一租约上串行、整体落在区块之前或之后且不会覆盖既有字节，其他租户的合法交错记录继续保留；目标文件不存在时仅在校验成功后才创建。生成的日志可由现有 verify、verify_all、verify_bytes、verify_all_bytes、read_tenant、export_tenant 与离线字节校验直接验证，import_tenant 的既有空链冲突语义保持不变。功能不依赖网络或远端锚定；JSONL 字段、租户身份区分、摘要算法、错误类型与既有入口的签名、返回值及行为保持兼容。

`append_many_stream(entries)` 是 append_many 的**单次消费流式**入口：调用方把一次性条目可迭代对象（生成器、迭代器、元组、集合、列表及自定义可迭代对象）直接交给跨租户原子追加，而不必先物化成列表。entries 必须是可迭代对象，但**单个 `bytes`、`bytearray`、`str`、`dict` 都不是条目容器**（前两者迭代产出整数、str 产出字符、dict 只是一个条目对象），连同任何不可迭代值（`None`、布尔、数字及其他无 `__iter__` 的值）一律视为参数错误并抛 `ValueError`；容器边界在读取历史、探测路径或开始提交之前确定。迭代器只被取得一次且**只向前消费一次**，按产生顺序逐项确认成员是**恰好**含 `tenant`、`event` 两键的对象（缺键、多键、键集合不符或非字符串成员键一律 `ValueError`），并对每个 tenant 与 event 递归执行与 append 完全相同的标准 JSON 校验（非字符串对象键、循环容器、NaN/Infinity/-Infinity 等非有限数字及无法无歧义编码的值都在触碰路径、加锁或读取任何历史字节之前以 `ValueError` 结束）；遇到首个非法成员立即停止索取后续元素。迭代器在产生完毕前自己抛出的异常**原样透传**（不包装成 ValueError），此前已消费的前缀同样不落盘。空迭代器在全部边界通过后直接返回 `[]`：**不创建、不读取也不改变日志**（即使历史已损坏也不扫描，已存在文件的字节保持不变）。全部输入通过后，行为与 append_many 接收同一列表**逐字段相同**：在一次排他数据文件租约内读取一致快照，只对本次涉及的每个租户执行与 append 完全相同的完整链扫描（从 `seq=1`、`prev=ZERO` 起逐条检查字段、顺序、prev 与 hash，其他租户记录可自由交错），损坏抛 `AuditChainStateError`、reason 只为 `missing`/`sequence`/`digest` 并沿用 tenant、seq、line 定位，多个涉及链同时损坏时按日志物理行号优先、输入首次出现顺序打破平局，未涉及租户的损坏忽略；任何失败路径都不写入部分记录、字节保持不变。状态有效时按输入顺序生成记录：租户分区沿用规范 JSON 身份（`1`、`1.0`、`true`、`"1"` 互不相干），重复出现的租户按该身份连续编号、逐条链接本组内前一条摘要，物理 JSONL 顺序与输入顺序一致，返回与输入一一对应、恰含 tenant/seq/event/prev/hash 五字段的记录列表；序列化（`sort_keys=True`、`allow_nan=False`）、摘要算法与末行缺换行时补换行规则与 append_many 完全一致，因此同一历史上对相同条目序列，本入口落盘的 JSONL 字节与 `append_many`（或按输入顺序逐条 append）**逐字节相同**。整组记录作为一个不可分割的追加区块由一次块写入提交：竞争写入在同一租约上串行、整体落在区块之前或之后，持共享锁的读取方只能看到提交前或提交后的完整历史；日志文件仅在成功调用时才创建。新入口不联网、不引入远端锚定或任何额外落盘格式；现有追加、条件追加、批量流式追加、迁移、读取、校验、比较与清单入口的签名、结果、异常字段及 JSONL 兼容语义保持不变。

`append_many_if_heads(entries)` 把跨租户原子追加与每租户链头断言合并为一次离线原子提交，相当于 `append_many` 的不可分割分组提交与每租户一个 `append_batch_if_head` 式头部断言的融合：entries 必须是列表，每项必须是**恰好**含 `tenant`、`events`、`expected_count`、`expected_hash` 四个键的对象（参数不是列表、成员不是对象、缺键、多键或键集合不符一律 `ValueError`；非字符串成员键同样拒绝）；events 必须是非空列表（非列表或空列表一律 `ValueError`——空 `entries` 列表才是校验通过后的空操作），其每个事件沿用与 append 完全相同的标准 JSON 边界；`expected_count` 必须是非负普通整数（`bool` 即使是 int 子类也拒绝，负数、浮点、字符串、`None` 及其他类型一律 `ValueError`），`expected_hash` 必须恰好是 64 个小写十六进制字符（长度不符、大写、非 hex 字符或非字符串一律 `ValueError`），空链断言使用现有 `ZERO`；同一规范 JSON 身份的 tenant 在整个 entries 中至多出现一次，重复（含仅对象键顺序不同但身份相同）一律 `ValueError`，而 `1`、`1.0`、`true`、`"1"` 等不同 JSON 身份仍是互不相关的租户。列表形状、成员形状、键集合、events 非空、计数/摘要格式、租户唯一性以及全部 tenant/event 的标准 JSON 边界都在加锁、探测路径或读取任何字节之前完成，任何非法输入统一抛 `ValueError` 且不创建文件、不读写字节，即使目标日志已损坏也不读取。空列表在全部校验通过后直接返回 `[]`：不创建、不读取也不改变日志，头部断言不被求值。非空调用在一次排他租约内读取一致快照，只对本次涉及的每个租户执行与 append 完全相同的完整链扫描——只验证涉及租户从 seq=1 到链尾的顺序、prev 与每条 hash，缺失或无法解析为 `missing`、序号错误为 `sequence`、前序或当前摘要不符为 `digest`，并以 `AuditChainStateError` 的 tenant、seq、line、reason 字段报告；多个涉及链同时损坏时按物理行号优先、输入首次出现顺序打破平局（与 append_many 完全一致），未涉及租户的损坏忽略。任何状态错误都不拿不可验证的链去比较断言、不写入任何字节。涉及链状态全部有效后，按 entries 顺序依次比较每个断言的计数与末条摘要，首个不符项（无论租户）按 entries 顺序抛 `AuditChainConflictError`，公开该租户的 `expected_count`、`expected_hash`、`actual_count`、`actual_hash`，`reason` 固定为 `"conflict"`，`actual_count` 为零时 `actual_hash` 为 `ZERO`；状态错误严格优先于冲突，冲突路径同样不写入任何字节。日志不存在时，只有**全部**断言都是 `(0, ZERO)` 才能创建文件；否则按 entries 顺序首个非空/错摘要断言在目录租约内确定性地抛出 actual 为 `(0, ZERO)` 的冲突，且不创建任何文件。全部断言匹配时，按 entries 顺序、每个 entry 内按 events 顺序生成并返回五字段记录（tenant、seq、event、prev、hash）列表：每个租户从其断言链尾（首条 prev 为 `expected_hash`）连续编号，同一 entry 的多条事件在批次内连续链接，字段、摘要算法、规范化序列化（`sort_keys=True`、`allow_nan=False`）、末行缺换行时补换行及租户身份规则与 append_batch、append_many 完全一致，落盘字节与对相同链头按相同 entry/event 顺序逐条调用 append 逐字节一致；所有记录作为不可分割 JSONL 区块一次追加，其他租户的合法交错记录继续保留。并发提交在同一排他租约上串行：竞争相同/相交链头的调用至多一个成功，其余在锁内观察到获胜者写入后的新链头并得到携带获胜后实际计数与末条摘要的确定冲突，持共享锁的读取方只能看到提交前或提交后的完整快照，绝不会看到半个区块。生成的日志可由 append、append_batch、append_if_head、append_batch_if_head、append_many、verify、verify_all、verify_bytes、verify_all_bytes、read_tenant、export_tenant/import_tenant 直接继续追加、校验、分页读取与离线迁移；功能不依赖网络或远端锚定，既有入口的签名、返回值、异常字段与可迁移 JSONL 格式保持兼容。

`export_tenant(tenant)` 面向离线迁移，按租户导出单链：返回 UTF-8 编码的 `bytes`，本身不创建、不改写、不删除任何文件，也不访问网络；调用方自行把返回字节写入新的 JSONL 路径后，新的 `AuditChain` 可直接用现有 verify/verify_all 离线验证。tenant 采用与 append/verify 完全相同的标准 JSON 边界，非法值在读取任何历史之前统一抛 `ValueError` 且不读取、不创建文件。导出在单次只读共享锁快照中完成：先运行与 `verify(tenant)` 相同的完整扫描，整份快照对该租户有效后才开始拼装结果，因此源状态错误统一抛 `AuditChainStateError`（填入目标 tenant、首个应检查的 seq、reason 与物理行号），绝不会先返回已收集的前缀；reason 仅为 missing、sequence、digest，优先级与行号沿用现有校验规则。源文件不存在或为空是合法空快照，成功返回 `b""`。导出内容只包含目标租户在源文件中按物理顺序出现的记录（其他租户的交错记录被丢弃且不导致重排），每行一个 JSON 对象，沿用 append 的序列化（`sort_keys=True`、`allow_nan=False`）与换行规则，字段、值、seq、prev、hash 与源历史语义一致；JSON 身份不同的租户（如 `1`、`1.0`、`true`、`"1"`）各自独立导出、互不混入。快照未变更时重复调用得到字节完全相同的结果；并发追加期间，导出只能观察到某次追加之前或之后的完整快照，失败时不写入任何字节。

`import_tenant(tenant, data)` 是 `export_tenant` 的离线反向入口：把一段单租户 JSONL 历史（通常来自另一条日志的导出字节）整体移植/灾备恢复到本日志，全程不依赖网络或远端锚定。调用先于任何历史读取、路径探测和加锁完成参数边界校验：tenant 沿用与 append/verify/export 完全相同的标准 JSON 边界（NaN/Infinity、非字符串键、循环容器及无标准 JSON 编码的值一律 `ValueError`），`data` 必须是 `bytes`（`str`、`bytearray` 及其他类型一律 `ValueError`），参数边界错误优先于一切历史状态处理，且不创建文件、不改字节。`data` 为空 `b""` 时在校验通过后直接返回 `[]`：不创建文件、不读取历史、不改变任何字节（即使目标日志已损坏也不读取）。非空 `data` 必须是严格 UTF-8、每行一个标准 JSON 对象的单租户历史；在触碰目标之前先完整校验整条输入链——从 `seq=1`、`prev=ZERO` 起逐行确认必需字段、连续顺序与摘要：解析失败、重复键、非标准数字、非法 UTF-8 或缺字段抛 `AuditChainStateError`、reason 为 `missing`，顺序错误为 `sequence`，prev 或 hash 不一致为 `digest`，并准确填充 tenant、seq 与物理行号（行号与优先级规则与 append/verify/export 完全一致）；混入任何其他规范 JSON 身份的租户记录（含交错的其他租户、`1` 与 `"1"` 这类不同身份）违反单租户输入契约，统一抛 `ValueError`。随后在同一次受保护操作（与 append 相同的数据文件排他租约；目标不存在时经目录租约原子创建）内校验目标文件：目标租户已有任何记录即抛 `AuditChainConflictError`，固定 `expected_count=0`、`expected_hash=ZERO`，`actual_count`/`actual_hash` 反映租约内观察到的目标尾部（含其他租户交错后的该租户真实尾摘要）；目标历史损坏时优先返回与 append 完全相同的 `AuditChainStateError`（状态错误优先于冲突判定），其他租户自身的摘要损坏不影响导入。任何失败路径都不写入部分记录、不改变既有字节。成功时把整段历史作为一个不可分割的字节块一次追加（目标最后一行缺换行时沿用 append 的补换行规则），记录原有的 tenant、seq、event、prev、hash 原样保留——既不重编号也不重算摘要，首条仍以 `ZERO` 为锚；返回按 seq 排列的记录 dict 列表（恰含五个现有字段及其输入原值）。目标文件可已包含其他租户的有效交错记录，导入后 verify、verify_all、verify_bytes、verify_all_bytes、export_tenant、read_tenant 均按现有规则通过，且该租户可直接用 append/append_if_head 从导入尾部继续；JSON 身份不同的租户互不可见、互不冲突。并发导入/追加同租户时，写操作在同一排他租约上串行：至多一次导入成功提交完整区块，其余调用要么观察到该租户非空链头而得到携带实际尾部的冲突，要么在导入之前成功并让随后的导入冲突；共享锁读取方只能看到整段导入之前或之后的完整快照。append、append_batch、append_if_head、append_batch_if_head、verify、verify_all、verify_bytes、verify_all_bytes、export_tenant、read_tenant 的签名、返回值、异常字段、租户身份区分、并发快照与 JSONL 可迁移格式保持不变。

`export_all()` 与 `import_all(data)` 是整份日志快照的离线迁移入口，分别对应 export_tenant/import_tenant 的全日志版本，JSONL 格式、摘要算法、租户身份规则与既有入口完全不变。`export_all()` 只读返回当前日志的 UTF-8 `bytes`：不创建、不改写、不删除任何文件，不访问网络；日志不存在或为空是合法空快照，返回 `b""`。返回前在同一次只读共享锁快照上按物理顺序验证所有租户的全部链（每个租户自首次出现起独立从 seq=1、prev=ZERO 校验，规则与 verify_all 一致）：物理行无法按严格 UTF-8 和标准 JSON 解析、含重复键或非标准数字，或任一租户出现缺字段、顺序错误、前序摘要错误或当前摘要错误时，不返回任何部分结果，改抛 `AuditChainStateError`（reason 仅为 missing、sequence、digest），以 tenant、seq、reason、line 定位物理顺序上的首次损坏——无法确定租户的行（不可解析、非对象、无 tenant 键）tenant 与 seq 为 None。验证通过后逐字节返回快照原文（含租户交错顺序），并发追加期间导出只能对应完整的追加前或追加后视图。`import_all(data)` 接收多租户交错的 JSONL 字节：`data` 不是 `bytes` 时在读取目标之前抛 `ValueError`；空 `bytes` 在类型检查通过后返回 `[]`，不创建文件、不读历史、不改字节。非空输入先在内存中完整验证：允许租户交错，但每个租户的链都从 seq=1、prev=ZERO 起连续，每条记录恰含 tenant、seq、event、prev、hash 五个既有字段且摘要可重算；解析失败、缺字段或多字段、重复键、非标准数字、非法 UTF-8 按 missing，序号问题按 sequence，prev 或 hash 不符按 digest，均抛带输入物理行号的 `AuditChainStateError`，物理顺序上首个损坏行决定结果。输入验证通过后，目标检查与提交在同一次排他租约内作为一次原子操作完成，且只检查输入涉及的租户：目标链损坏优先抛与 append 相同字段的 `AuditChainStateError`（多链同时损坏按目标物理行优先、输入首次出现顺序打破平局）；涉及租户已有记录时按输入首次出现顺序抛 `AuditChainConflictError`，`expected_count` 固定为 0、`expected_hash` 固定为 `ZERO`，`actual_count`/`actual_hash` 反映租约内观察到的该租户尾部；任何失败路径都不写入字节。全部涉及链为空时，才把规范化 JSONL（`sort_keys=True`、`allow_nan=False`，每行一条记录）作为一个不可分割区块一次追加，目标末行缺换行时沿用 append 的补换行规则，目标不存在时仅在校验通过后创建；成功返回按输入物理顺序排列、保留原值的记录 dict 列表。竞争导入或追加在同一租约上串行，共享锁读取方只能看到完整提交前或提交后的状态。append、append_batch、append_if_head、append_batch_if_head、append_many、append_many_if_heads、verify、verify_all、verify_bytes、verify_all_bytes、export_tenant、import_tenant、read_tenant、head、heads 的签名、返回值、异常字段与既有语义保持不变。

`export_tenant_range(tenant, start_seq, end_seq=None)` 与 `import_tenant_range(tenant, data, expected_count, expected_hash)` 是非空链的分段迁移入口：归档或灾备恢复可以从一个已知链头继续，而不必每次搬运整份历史；五字段记录、seq 编号与摘要算法与既有入口完全一致。`export_tenant_range` 只读返回目标租户闭区间 `[start_seq, end_seq]` 的 UTF-8 JSONL `bytes`（`end_seq=None` 表示到链尾），不创建、不改写、不删除任何文件，不访问网络；记录原样保留磁盘上的 prev 与 hash，因此首条记录的 prev 仍指向被省略的前序链头。tenant 沿用与 append/verify/export 相同的标准 JSON 边界，`start_seq` 必须是正的普通整数（拒绝 bool、浮点及其他类型），`end_seq` 必须是 `None` 或不小于 `start_seq` 的普通整数，非法边界在读取任何历史之前抛 `ValueError`。导出在单次只读共享锁快照中先以与 `verify(tenant)` 完全相同的规则完整校验该租户整条链——源历史损坏抛与 append/verify/export_tenant 相同字段的 `AuditChainStateError`，即使请求区间完全位于损坏点之前也绝不返回已验证前缀——校验通过后才在内存中截取闭区间。空链（日志不存在、为空或该租户无记录）或范围超出链尾（`start_seq` 大于当前条数，或显式 `end_seq` 大于当前条数）抛新增的 `AuditChainRangeError`，公开 `tenant`、`start_seq`、`end_seq`（按调用原值，未给 `end_seq` 时为 `None`）、`count`（快照内验证过的链长），`reason` 固定为 `"range"`，且不返回任何字节。`import_tenant_range` 是反向入口：先校验参数——tenant 标准 JSON 边界、`data` 只能是 `bytes`、`expected_count` 必须是非负普通整数（拒绝 bool）、`expected_hash` 必须恰好是 64 个小写十六进制字符（空链断言用 `ZERO`）——非法值在读取前抛 `ValueError`；空 `bytes` 在校验通过后返回 `[]`，不创建文件、不读历史、不改字节。非空输入在触碰目标之前完整校验：严格 UTF-8 JSONL、每条物理行都是同一规范 JSON 身份租户且**恰好**含五个既有字段（多字段同样按 missing 处理）、seq 从 `expected_count + 1` 起连续递增、第一条 prev 等于 `expected_hash`、每条 hash 可重算；缺失/顺序/摘要错误分别以 `missing`/`sequence`/`digest` 报告首个物理行（`AuditChainStateError`，tenant/seq/line 填充规则与 append 一致），混入其他租户身份违反单租户输入契约抛 `ValueError`。随后在原子提交中（与 append_if_head 相同的租约：已存在日志用数据文件排他锁，不存在时目录租约覆盖"探测—空链比较—创建"整段）先以与 append 完全相同的规则校验目标完整链——目标损坏优先抛 `AuditChainStateError`——再同时比较实际 count 与末条 hash，二者都与断言匹配才把整段作为一个不可分割字节块追加（末行缺换行时沿用 append 的补换行规则）并返回按 seq 排列的记录 dict 列表；断言不符抛带 `actual_count`、`actual_hash` 的 `AuditChainConflictError`（`reason` 固定 `"conflict"`），目标不存在时只有 `(0, ZERO)` 断言可创建文件，其余非空断言确定性冲突且不创建文件；任何失败路径都不写入字节。并发提交在同一租约上串行：至多一个获胜，其余在锁内观察到获胜后的真实链头并得到携带实际值的冲突。既有入口（append 系列、verify 系列、export_tenant/export_all/import_tenant/import_all、read_tenant、head/heads）的签名、返回值、异常字段、并发快照与可迁移 JSONL 格式保持不变。

`import_all_range(data, expected_heads)` 是多租户分段迁移入口：把多个租户从各自已知链头开始的 JSONL 片段（通常由若干次 export_tenant_range 产生，允许租户交错）在一次离线原子提交中追加到本日志，是 import_tenant_range 的跨租户版本，也是 import_all 从已知头部续写而非空链嫁接的推广。记录原样保留 tenant、seq、event、prev、hash——既不重编号也不重算摘要——因此 verify/verify_all/verify_bytes/verify_all_bytes 与 export 系列按既有规则即可校验合并后的日志。参数边界先于一切：`data` 必须是 `bytes`（`str`、`bytearray` 及其他类型一律 `ValueError`），`expected_heads` 必须是列表（其他类型一律 `ValueError`），每个成员必须是**恰好**含 `tenant`、`expected_count`、`expected_hash` 三个键的对象（缺键、多键、键集合不符或非字符串成员键同样拒绝）；tenant 沿用与 append/verify/export 完全相同的标准 JSON 边界，`expected_count` 必须是非负普通整数（`bool` 即使是 int 子类也拒绝，负数、浮点、字符串、`None` 及其他类型一律 `ValueError`），`expected_hash` 必须恰好是 64 个小写十六进制字符（空链断言用现有 `ZERO`）；同一规范 JSON 身份的 tenant 在整个 expected_heads 中至多出现一次（仅对象键顺序不同但身份相同同样 `ValueError`），而 `1`、`1.0`、`true`、`"1"` 仍是互不相干的租户。所有形状、键集合、租户/计数/摘要格式与唯一性校验都在加锁、探测路径或读取任何字节之前完成，任何非法输入统一抛 `ValueError` 且不创建文件、不读写字节，即使目标日志已损坏也不读取。`data` 为空 `b""` 时在全部参数校验通过后直接返回 `[]`：不创建文件、不读取历史、不改变任何字节，头部断言不被求值。非空输入在触碰目标之前先在内存中完整校验：严格 UTF-8 JSONL，输入允许租户交错，但每租户首条 `seq=expected_count+1`、`prev=expected_hash`，之后连续递增；每条物理行必须是恰含 tenant、seq、event、prev、hash 五个既有字段的对象，且每条 hash 按现有算法可重算；每个被列出的租户至少出现一条记录。解析失败、重复键、非标准数字、空行、非对象、缺字段或多字段、非法 UTF-8、以及缺记录的已列出租户抛 `AuditChainStateError`、reason 为 `missing`；序号问题为 `sequence`；prev/hash 不符为 `digest`；异常携带 tenant、seq、line（输入物理行号），无法确定租户时 tenant 与 seq 为 `None`；出现未列入 expected_heads 的其他规范 JSON 身份租户记录违反输入契约，按物理行首个决定的优先级抛 `ValueError`（与 import_tenant 的外来租户规则一致）；多处问题按物理行首个决定（输入问题整体优先于目标状态），输入校验失败不读取目标、不写入任何字节。随后目标扫描、断言比较与写入在同一次排他租约内完成（与 append_many_if_heads 相同的租约：已存在日志用数据文件排他锁，日志不存在时目录租约覆盖"探测—空链比较—创建"整段）：只扫描本次涉及租户的目标链，未涉及租户的损坏忽略；目标损坏优先抛与 append 字段相同的 `AuditChainStateError`（多链同时损坏按目标物理行号优先、expected_heads 顺序打破平局），绝不拿不可验证的链去比较断言。涉及链全部有效后，按 expected_heads 顺序依次比较 count 与末条 hash，首个不符项抛 `AuditChainConflictError`，公开该租户的 `expected_count`、`expected_hash`、`actual_count`、`actual_hash`，`reason` 固定为 `"conflict"`，`actual_count` 为零时 `actual_hash` 为 `ZERO`；冲突路径不写入任何字节。目标不存在时只有**全部**断言都是 `(0, ZERO)` 才能创建文件，否则按列表顺序首个非空/错摘要断言确定性地以 actual `(0, ZERO)` 冲突返回且不留任何文件。成功时按输入物理顺序返回保留原值的记录 dict 列表，以现有规范 JSONL（`sort_keys=True`、`allow_nan=False`，末行缺换行时补换行）作为一个不可分割区块一次追加，不重编号、不重算；其他租户已在盘上的合法交错记录继续保留，持共享锁的读取方只见提交前或提交后的完整快照。并发提交在同一排他租约上串行：竞争相同/相交链头的调用至多一个成功，其余在锁内观察到获胜者写入后的真实链头并得到携带实际值的确定冲突。生成的日志可由 append 系列、verify 系列、read_tenant、export/import 系列直接继续追加、校验、分页读取与离线迁移；功能不依赖网络或远端锚定，既有入口的签名、返回值、异常字段、租户身份、JSONL 字节语义与本地离线约束保持不变。

`read_tenant(tenant, start_seq=1, page_size=None)` 是只读的按租户分页读取入口：返回按该租户 `seq` 升序排列的记录列表，每项保留 tenant、seq、event、prev、hash 五个现有字段及其磁盘原值；列表只包含目标租户，其他租户的交错记录既不出现也不改变分页顺序（分页只按目标租户自己的 1..count 计数）。`start_seq` 必须是大于等于 1 的普通整数（拒绝 bool、浮点及其他类型），缺省 1 表示从第一条开始；`page_size` 必须是正的普通整数或 `None`，`None`（缺省）表示读到链尾。起始序号超过当前条数、或末页不足 page_size 都不是错误：返回相应后缀，可能为 `[]`。tenant、start_seq、page_size 在读取任何历史之前全部校验——tenant 沿用与 append/verify/export 相同的标准 JSON 边界，NaN、Infinity、-Infinity、非字符串对象键、循环容器及布尔/其他非标准值统一抛 `ValueError`，非法分页参数同样抛 `ValueError`，且不创建、不修改任何文件。读取在单次只读共享锁快照中完成（与 verify/export 相同）：先以与 `verify(tenant)` 完全相同的 JSON 身份与摘要规则扫描该租户从第一条到链尾的完整历史，整份快照对该租户有效后才在内存中截取所请求页；因此并发追加只能让本次结果对应某次追加之前或之后的完整快照，绝不会出现撕裂页，且即使请求页位于损坏点之前，缺字段、非法 UTF-8 或 JSON、序号不连续、前序摘要不匹配或当前摘要重算不一致都会使整个调用抛出 `AuditChainStateError` 而绝不返回已验证前缀，定位字段（tenant、seq、reason、line）与 verify/append/export_tenant 完全一致，reason 仅为 missing、sequence、digest 并优先报告首次发现的位置。目标租户不存在或日志不存在视为空链，成功返回 `[]`。该入口不写分页缓存、不改动原始字节、不依赖网络；append、append_batch、verify、verify_all、verify_bytes、verify_all_bytes、export_tenant 的签名、返回值、异常边界、并发一致性及可迁移日志格式保持不变。

`verify_bytes(data, tenant, expected_count=None)` 与 `verify_all_bytes(data)` 是纯内存离线校验入口：调用方把 JSONL 历史的原始 `bytes` 直接传入（`export_tenant` 导出的单租户字节，或包含交错租户的完整日志均可），入口绝不读取、创建或修改构造器所指向的路径，也不依赖网络、远端锚定或其他服务；结果只依据传入快照，调用期间不修改 `data`。两个入口复用与 verify/verify_all 完全相同的 JSON 标准化、租户身份与摘要算法逐行校验，因此返回结构、reason 分类（missing/sequence/digest）、`at` 口径、租户首次出现顺序与计数与文件入口逐字节一致；空 `bytes` 是成功的空历史（`verify_bytes` 返回 `{"ok": True, "count": 0}`，`verify_all_bytes` 返回 `{"ok": True, "tenants": []}`），且不创建任何文件。空行、非对象、缺字段、重复键、非标准数字（NaN/Infinity/溢出数）、非法 UTF-8 或 JSON 解析失败一律按 missing 处理，能定位的物理行使用行号；seq 不连续为 sequence，prev 或 hash 不符为 digest；其他租户的坏行同样会被发现，且更早的错误优先。`verify_bytes` 的 expected_count 短缺报 missing、超额报 sequence，与 verify 同口径；`data` 不是 `bytes`（含 `bytearray`/`str` 等）、tenant 越过标准 JSON 边界（NaN/Infinity、非字符串键、循环容器等），或 expected_count 不是 `None` 以外的非负整数（`bool` 同样拒绝）时，在任何解析之前抛出 `ValueError`，不泄漏底层解析异常。export_tenant 生成的字节写回另一个 `AuditChain` 后，文件校验与内存校验得到相同的摘要和计数。append、append_batch、verify、verify_all、export_tenant 的签名、格式、错误类型、并发快照及损坏前序拒绝行为保持不变。

记录序号 `seq` 的校验是严格的 JSON 整数校验：append 系列只产生从 1 开始连续递增的整数序号，因此历史中每条记录的 `seq` 必须是不带小数和指数表示的 JSON 整数，且恰好等于该租户下一个期望序号。`1.0`、`1e0`、`1E0`、`10e-1` 等浮点拼写（即使宿主语言宽松相等成立）、`true`/`false`、字符串、`null`、数组、对象，以及任何不等于期望值的整数（含负数与零），统一判为 `sequence` 损坏；缺少 `seq` 字段或整行不可解析仍判 `missing`，分类优先级不变。该规则在 append、append_batch、append_if_head、append_batch_if_head、append_many、append_many_if_heads、import_tenant、verify、verify_all、head、heads、read_tenant、export_tenant、verify_bytes、verify_all_bytes 全部公开入口一致生效，文件扫描与内存扫描对同一损坏行给出相同结论：`sequence` 错误把期望序号、租户与物理行号填入 `AuditChainStateError`（verify 系结果继续使用现有 `ok`/`at`/`tenant`/`reason` 结构），物理顺序上更早的 missing/sequence/digest 优先，`expected_count` 对合法历史的短缺/超额语义不变。非法序号不会被重编号、跳过、重写或当作另一租户：任何写入入口遇到该状态都拒绝追加且保持原字节不变，`import_tenant` 对含非法序号的输入或目标同样整体失败、不留部分导入；非法调用参数仍在读取历史之前以 `ValueError` 结束。
`export_tenant_chunks(tenant, chunk_size)` 与 `export_all_chunks(chunk_size)` 是面向大历史的分块离线导出入口，分别是 `export_tenant`/`export_all` 的分块版本：不创建、不改写、不删除任何文件，不访问网络，也不写额外落盘元数据。两者都返回一个产生 `bytes` 的迭代器，按顺序产出的分块拼接后分别与同一份快照上 `export_tenant(tenant)`、`export_all()` 的返回值**逐字节相等**；分块只按字节偏移切分，可切在任意 UTF-8 序列、JSON 对象或换行中间，最后一块可以更短，空历史（日志不存在、为空，或目标租户无记录）产出空迭代（零个分块）。tenant 沿用与 append/verify/export 完全相同的标准 JSON 边界；`chunk_size` 必须是正的普通整数（`bool` 即使是 int 子类也拒绝，`0`、负数、浮点、字符串及其他类型一律 `ValueError`），所有边界错误在产生迭代器或读取历史之前抛出。整次导出固定于一个完整快照：在同一次只读共享锁快照上先完成与对应非分块入口完全相同的全链校验（单租户即 `verify(tenant)` 的扫描，全日志即 `verify_all` 的物理顺序扫描），**首块产生之前**校验必须全部通过；源历史损坏时不产出任何分块，改抛 `AuditChainStateError`，其 tenant、seq、reason、line 与 `export_tenant`/`export_all` 完全一致，并发追加只能让各次导出对应某次追加之前或之后的完整快照。

`import_tenant_chunks(tenant, chunks)` 与 `import_all_chunks(chunks)` 是对应的分块离线导入入口，分别是 `import_tenant`/`import_all` 的大历史版本：调用方按顺序提供一个 `bytes` 分块可迭代对象，单个 `bytes` 或 `bytearray` 不能被当作容器（其迭代会产出整数，统一 `ValueError`），不可迭代容器或任何非 `bytes`（`bytearray` 元素同样拒绝）成员也是 `ValueError`，遇到首个坏成员立即停止消费后续分块；空分块允许，空可迭代或仅含空分块等价于空内容。分块只按字节拼接，可切在任意字节位置（UTF-8、JSON、换行中间），只有按序拼接后的整段才被解析。二者分别接受现有 `import_tenant`、`import_all` 可接受的完整内容，字段、优先级与字节入口完全一致：`import_tenant_chunks` 的 tenant 沿用标准 JSON 边界，混入其他规范 JSON 身份租户抛 `ValueError`；非法 JSONL、缺字段、顺序或摘要错误抛带输入物理行号的 `AuditChainStateError`，目标涉及租户已有记录抛 `AuditChainConflictError`（固定空链期望、actual_* 反映租约内尾部），且一切输入问题严格优先于目标状态。空拼接在边界校验通过后返回 `[]`，不创建文件、不读取历史、不改字节。成功时按物理顺序返回与对应字节入口**相同的记录对象**（保留 tenant/seq/event/prev/hash 原值），并把整段内容作为**一次不可分提交**写入（末行缺换行沿用 append 的补换行规则）；任何输入或目标失败都不写入部分字节，持共享锁的并发读取者只能看到提交前或提交后的完整状态，竞争同一空链头的分块导入在同一排他租约上串行、恰有一个获胜。新接口不依赖网络、远端锚定或额外落盘元数据；所有既有追加、条件头、分页读取、verify 系列、范围迁移及非分块导入导出的行为、签名、返回值、异常字段、租户隔离与规范 JSONL 字节格式保持不变。

`export_tenant_range_chunks(tenant, start_seq, end_seq=None, chunk_size=None)`、`import_tenant_range_chunks(tenant, chunks, expected_count, expected_hash)` 与 `import_all_range_chunks(chunks, expected_heads)` 是**范围迁移的分块入口**，分别是 `export_tenant_range`、`import_tenant_range` 与 `import_all_range` 的大历史分块版本，让大租户的分段迁移可以按块传输而不必拼成单个 bytes。`export_tenant_range_chunks` 返回产生 `bytes` 的迭代器，按顺序拼接后与同一快照上 `export_tenant_range(tenant, start_seq, end_seq)` 的返回值**逐字节相等**；分块只按字节偏移切分，可切在任意 UTF-8 序列、JSON 对象或 LF 中间，每块不超过 `chunk_size`，最后一块可以更短。导出侧先校验 tenant（标准 JSON 边界）、`start_seq`（正的普通整数）、可选 `end_seq`（`None` 或不小于 `start_seq` 的普通整数）与 `chunk_size`（正的普通整数）——bool、负数、浮点、字符串及其他类型统一在产生迭代器或读取任何历史之前抛 `ValueError`；随后整次导出固定于一个完整快照：与 `export_tenant_range` 完全相同的全链校验与区间检查在**首块产生之前**完成，源历史损坏抛相同字段的 `AuditChainStateError`，空链、起点越过链尾或终点越界抛携带 tenant、范围与已验证 count 的 `AuditChainRangeError`，绝不产出部分块。两个导入入口接收按顺序排列的 `bytes` 分块，空块允许、可切在任意字节位置，只有按序拼接后的整段才被解析；单个 `bytes`/`bytearray` 不算容器、不可迭代容器或首个非 `bytes` 成员统一在读取目标之前抛 `ValueError`，遇错立即停止消费。单租户入口的 tenant、`expected_count`、`expected_hash` 与多租户入口的 `expected_heads` 都在**消费任何分块之前**按对应非分块入口的规则校验（非法值一个分块都不会被拉取）。拼接后的内容须是严格 JSONL 并按声明头部连续链接：混入其他规范 JSON 身份租户（单租户入口）或未列入 `expected_heads` 的租户（多租户入口）抛 `ValueError`，输入缺失、顺序或摘要问题抛带 tenant、seq、reason、line 的 `AuditChainStateError`，目标头不匹配抛 `reason` 固定 `"conflict"` 且携带双方头部字段的 `AuditChainConflictError`。空拼接在校验通过后返回 `[]`，不创建文件、不读历史、不改字节。成功时整段作为**一次不可分割追加**提交（末行缺换行沿用 append 的补换行规则），返回的记录顺序和字段与对应非分块入口完全相同；任何失败路径都不写入部分字节，持共享锁的并发读取者只见提交前或提交后的完整状态。新入口不依赖网络、远端锚定或额外落盘元数据；既有 append 系列、范围导入导出、整链分块入口、离线校验与并发读取行为的签名、返回值、异常字段与 JSONL 字节语义保持不变。

`heads_bytes(data)` 与 `heads_chunks(chunks)` 是离线快照的多租户链头目录，分别是 `heads()` 的纯内存字节版与分块版：只消费调用方给出的内存数据，绝不读取、创建或修改构造器所指向的路径，不访问网络、不依赖远端锚定，也不写缓存或落盘索引。`heads_bytes(data)` 的 `data` 必须恰好是 `bytes`——`bytearray`、`str` 及其他一切类型统一在任何解析之前抛 `ValueError`（不泄漏底层解码/解析异常）。`heads_chunks(chunks)` 接受按文件顺序排列的 `bytes` 分块可迭代对象，分块边界与 `verify_all_chunks` 完全一致：单个 `bytes` 或 `bytearray` 不能被当作容器（其迭代会产出整数）、不可迭代对象、以及首个非 `bytes`（含 `bytearray`、`str`）成员统一 `ValueError`，遇错立即停止消费后续分块；空 `bytes`、空可迭代或仅含空分块都表示空历史。分块只按字节拼接，可切在任意字节位置（UTF-8 序列、JSON 对象、LF 中间），只有拼接后的整段才被解码，因此 `heads_chunks(chunks)` 与对相同拼接字节调用 `heads_bytes` 的结果**逐字段相等**，切入位置不改变任何语义。边界通过后，两入口复用 `verify_all_bytes` 的严格 UTF-8、LF 唯一行界、标准 JSON（重复键、NaN/Infinity/-Infinity 及溢出数等非标准数字一律拒绝）规则，按规范 JSON 租户身份分别从 `seq=1`、`prev=ZERO` 起校验每条租户链：空快照成功返回 `{"ok": True, "tenants": []}`；非空成功返回与 `heads()` 相同形状的对象，`tenants` 按租户首次出现的物理顺序排列，每项保留原始 tenant 值并给出已验证的 `count` 与末条 `hash`——正是离线条件追加（`append_if_head`/`append_batch_if_head`/`append_many_if_heads` 及 `import_*_range` 系列）所需的 `expected_count` 与 `expected_hash`，空链对应 `(0, ZERO)`。首个无法严格 UTF-8 解码或严格解析、非对象、缺既有字段、重复键、非标准数字的物理行返回与 `verify_all_bytes` 逐字段一致的失败对象，`ok` 为 `false`、`reason` 为 `missing`（无法确定租户时 `tenant` 为 `None`）；某租户序号不等于其下一期望序号为 `sequence`，`prev` 或 `hash` 不符为 `digest`，此时 `tenant` 为该行租户、`at` 为物理行号。失败对象只报告首个 `at`、`tenant`、`reason`，绝不返回部分 `tenants`。`heads`、`verify_all_bytes`、`verify_all_chunks` 及现有追加、导入导出、JSONL 格式、租户身份区分与并发行为保持不变。

`verify_heads(expected_heads)`、`verify_heads_bytes(data, expected_heads)` 与 `verify_heads_chunks(chunks, expected_heads)` 是**期望头校验**入口：`verify_all` 只能证明快照内部自洽，这三个入口进一步证明备份方保存的租户头目录与快照实际链头逐项一致，用于服务迁移、恢复与离线备份核对完整历史，不改变任何既有接口，也不依赖网络或远端锚定。`expected_heads` 是一个有序列表，列表顺序就是冲突优先级；每项必须是**恰好**含 `tenant`、`count`、`hash` 三个键的对象（参数不是列表、成员不是对象、缺键、多键或键集合不符一律 `ValueError`）。`tenant` 沿用与 append/verify/heads 完全相同的标准 JSON 边界；`count` 必须是非负普通整数（`bool` 即使是 int 子类也拒绝，负数、浮点、字符串、`None` 及其他类型一律 `ValueError`）；`hash` 必须恰好是 64 个小写十六进制字符（长度不符、大写、非 hex 字符或非字符串一律 `ValueError`），空链头使用现有 `ZERO`；同一规范 JSON 身份的 tenant 在整个列表中至多出现一次（仅对象键顺序不同但身份相同同样 `ValueError`），而 `1`、`1.0`、`true`、`"1"` 仍是互不相干的租户。这些形状、键集合、tenant/count/hash 格式与租户唯一性校验都在读取快照、探测路径或解析任何字节**之前**完成：`verify_heads_bytes` 的 `data` 不是 `bytes`、`verify_heads_chunks` 的分块容器/成员不合法同样在解析前以 `ValueError` 结束（分块容器边界与 `verify_all_chunks`/`heads_chunks` 完全一致：单个 `bytes`/`bytearray` 不算容器、不可迭代容器、首个非 `bytes` 成员立即停止消费；`expected_heads` 先于分块容器校验，因此非法期望值一个分块都不会消费），任何边界错误都严格优先于损坏快照的失败判定与头部比较。边界通过后，所有输入先复用现有严格 UTF-8、LF 唯一物理行边界、标准 JSON（拒绝重复键与非标准数字）以及 missing/sequence/digest 规则校验**完整快照**：首个损坏点返回与 `verify_all_bytes`/`heads_bytes` **逐字段一致**的失败对象（`{"ok": False, "at", "tenant", "reason"}`，无法确定租户时为 `None`），此时**不进行任何头部比较**（文件入口同样返回该失败对象，不抛异常、不写字节）。只有快照完全自洽后才比较头目录：先严格按 `expected_heads` 列表顺序逐租户比较 `count` 与末条 `hash`——目录中缺失的租户其实际头固定为 `(0, ZERO)`（恰好与空期望一致则匹配，否则冲突）；再处理目录中存在但列表未列出的租户，按快照首次出现顺序把它们视为期望 `(0, ZERO)` 的多余头。首个不相等结果抛 `AuditChainConflictError`，`reason` 固定 `"conflict"`，并填充 `tenant`、`expected_count`、`expected_hash`、`actual_count`、`actual_hash`（`actual_count` 为零时 `actual_hash` 为 `ZERO`；期望字段取冲突项的期望值，目录外租户的 `expected_count`/`expected_hash` 为 `0`/`ZERO`），任何冲突绝不写入字节。全部一致时返回与 `heads_bytes` 相同的成功结构 `{"ok": True, "tenants": [...]}`，保留快照的租户首次出现顺序、原始 tenant、已验证 `count` 与末条 `hash`；空快照与空目录（`expected_heads=[]`）匹配时返回 `{"ok": True, "tenants": []}`。`verify_heads` 对文件只取一次共享锁快照（与 verify_all/heads 相同的只读视图），是只读操作，不创建、不修改也不缓存文件；`verify_heads_bytes`/`verify_heads_chunks` 只消费调用方数据，绝不读取、创建或修改构造器路径，不访问网络、不写缓存或落盘索引，也不修改传入的字节、分块与期望列表；分块只按字节拼接、可切在任意 UTF-8/JSON/LF 位置，对相同拼接字节与 `verify_heads_bytes` 的结果逐字段相等。现有追加并发锁、JSONL 格式、分区规则、异常优先级以及全部 append/import/export/read/verify/heads 行为、签名、返回值与异常字段保持不变。

`compare_bytes(left_data, right_data)` 是**纯内存双快照备份核对**入口：只接收两个 JSONL `bytes` 快照并逐租户比较记录逻辑值，全程不读取、不创建、不修改构造器指向的 AuditChain 路径，不访问网络、不依赖远端锚定，也不修改两个入参的任何字节；JSONL 字节语义、租户身份规则、摘要算法与既有入口完全不变。两个快照可按不同物理顺序交错同一批租户——比较按规范 JSON 租户身份（与 append/verify_all 同一 `json.dumps(..., sort_keys=True)` 身份：对象键序不影响身份，而 `1`、`1.0`、`true`、`"1"` 互不相干）与每租户从 1 起的 `seq` 对齐记录，物理交错顺序本身不算差异；返回结构中租户身份值保留该侧首次出现该租户时的原始值（差异的租户值优先取左侧首次出现值）。类型边界最先执行且先于一切解析：任一入参不是恰好 `bytes`——包括 `bytearray`、`str` 及其他任何类型——立即抛 `ValueError`，两个快照都不解析。类型通过后，两侧都先复用现有 `verify_all_bytes` 的完整规则检查严格 UTF-8、LF 唯一物理行边界、标准 JSON（重复键、NaN/Infinity/-Infinity 及溢出数等非标准数字一律拒绝）、字段集合、租户身份、序号、prev 与 hash；任一快照损坏则**不进行比较**，返回 `{"ok": false, "side": "left"或"right", "at": 物理行号, "tenant": 租户或null, "reason": "missing"/"sequence"/"digest"}`，失败字段与 `verify_all_bytes` 逐字段一致只额外附 `side`；两侧都损坏时固定先报告 `left`（右侧根本不参与判定）。两个空快照彼此相等；任一侧未出现的合法规范租户按空链处理。两侧都有效后，按 left 租户首次出现顺序、再接 right 独有租户（按其首次出现顺序）确定租户比较顺序，逐租户从 seq 1 起比较对齐记录的逻辑值：tenant 与 seq 由对齐保证，只比较 `event`、`prev`、`hash`。完全相等返回 `{"ok": true, "equal": true, "tenants": [...]}`，每项按上述比较顺序保留原始租户、`count` 与末条 `hash`（空链 hash 为 `ZERO`，但 tenants 只列至少在一侧出现的租户）。首个差异返回 `{"ok": true, "equal": false, "tenant": ..., "seq": ..., "reason": ..., "left": 记录或null, "right": 记录或null}`：两侧同 seq 都有记录但 `event`、`prev` 或 `hash` 任一不同时 reason 为 `"different"`，左右记录原样附上；一侧链更长时，首个缺失位置按缺失侧报 `"missing_left"`（left 为 null）或 `"missing_right"`（right 为 null），存在侧附上该条记录。结果只报告按上述租户顺序与 seq 顺序确定的唯一一个位置，绝不连锁重复报告后续摘要差异。追加、批量追加、各类条件头追加、import/export 系列、读取、verify 系列、head/heads 查询及分块入口的既有签名、异常优先级、并发锁、租户隔离、JSONL 字节语义与错误含义保持不变。

`compare_chunks(left_chunks, right_chunks)` 是 `compare_bytes` 的**分块纯内存双快照备份核对**入口：两侧 JSONL 快照各按文件顺序以 `bytes` 分块可迭代对象到达，调用方不必先把任一侧拼成单个 bytes。每个参数都必须是分块容器——单个 `bytes` 或 `bytearray` 不能当容器（其迭代会产出整数，统一 `ValueError`），不可迭代容器、以及首个非 `bytes`（含 `bytearray`、`str`）成员同样 `ValueError`，任一侧遇到首个非法成员立即停止消费该侧后续分块；空分块允许，空可迭代或仅含空分块表示空快照。分块只按字节拼接，可切在任意字节位置（UTF-8 序列、JSON 对象、LF 中间），只有按序拼接后的整段才被解码。边界严格先于一切内容校验且按先左后右执行：先完整校验并消费左侧容器，再触碰右侧——左侧任何边界错误（即使右侧也有边界错误或其拼接损坏）固定优先于右侧，而任一侧任何边界错误都优先于两侧的快照内容校验（因此右侧分块成员非法时即使左侧拼接是损坏快照也先抛 `ValueError`）。两侧都通过边界后，入口对两侧拼接字节调用与 `compare_bytes` 完全相同的逻辑，故其结果与对相同拼接字节调用 `compare_bytes(left_concat, right_concat)` **逐字段相等**，切分位置不改变任何语义：两侧都先按严格 UTF-8、LF 唯一物理行边界、标准 JSON（重复键、NaN/Infinity/-Infinity 及溢出数等非标准数字一律拒绝）、字段集合、规范 JSON 租户身份以及每租户从 1 起的 seq、prev、hash 规则完整校验，一侧损坏返回 `{"ok": false, "side", "at", "tenant", "reason"}`（missing/sequence/digest 口径与 `verify_all_bytes` 一致），两侧都损坏固定先报告 left；两侧均有效后忽略租户在文件中的物理交错顺序，按左侧首次出现租户、再到右侧独有租户（按其首次出现顺序）确定比较顺序，每条链从 seq 1 起比较 `event`、`prev`、`hash`，完全相等返回与 `compare_bytes` 相同的 `{"ok": true, "equal": true, "tenants": [...]}`，首个差异返回相同的 `{"ok": true, "equal": false, "tenant", "seq", "reason", "left", "right"}`，reason 区分 `"different"`（两侧记录原样附上）、`"missing_left"`、`"missing_right"`（缺失侧为 null、存在侧附原始记录），只报告唯一一个位置，绝不连锁报告后续摘要变化。与 `compare_bytes` 一样，该入口是纯离线操作：不读取、不创建、不修改构造器指向的 AuditChain 路径，不访问网络、不依赖远端锚定，不写缓存或落盘索引，也不修改任何输入分块；现有 append、append_batch、条件追加、导入导出、分页读取、verify、head/heads、`compare_bytes` 及其他分块入口的签名、结果、异常字段、锁与 JSONL 字节格式保持不变。

`compare(other)` 是**面向日志路径的只读双快照核对**入口：`other` 必须恰好是另一个 `AuditChain` 实例，调用方不必自行读取任一日志。类型边界最先执行且先于任何路径读取——`other` 不是 `AuditChain`（含字符串/`Path`、bytes、dict 及其他一切类型）时立即抛 `ValueError`，两侧路径都不被打开或探测，也不会因类型错误创建任何文件。类型通过后，每侧只取**一次完整快照**：对该侧路径执行与 verify_all/heads/export_all 相同的只读共享锁读取，因此每侧观察到的永远是某次追加之前或之后的完整 JSONL 状态，绝不会把半行或跨越两次追加的拼接内容交给比较；并发追加只会决定某次调用恰好对应两侧各自的哪一个完整追加前/后状态。路径尚不存在是合法的追加前视图，按空历史（空字节快照）处理。当两个实例指向**同一路径**时（含分别用 `str` 与 `Path` 构造的等价路径），快照只读取一次并同时充当左右两侧，使同路径比较不可能落入两个不同的追加窗口，结果稳定地表示自身相等。随后两份快照**原样**交给现有 `compare_bytes`，因此结果与把这两份实际快照直接传给 `compare_bytes(left_snapshot, right_snapshot)` **逐字段一致**：两侧都先按 `verify_all_bytes` 的全部规则校验严格 UTF-8、LF 唯一物理行界、标准 JSON（重复键、NaN/Infinity/-Infinity 及溢出数等非标准数字一律拒绝）、字段集合、规范 JSON 租户身份、每租户从 1 起连续的 seq 以及 prev/hash 链接；任一侧损坏时不进入逻辑比较，返回与 `compare_bytes` 相同形状的失败结果 `{"ok": false, "side": "left"或"right", "at": 首个物理行号, "tenant": 该行租户或null, "reason": "missing"/"sequence"/"digest"}`，两侧都损坏时固定先报告 left（右侧不参与判定）。两侧都有效后，按规范 JSON 租户身份与每租户 seq 对齐记录，忽略文件中的物理交错顺序，完整保留 `compare_bytes` 对租户原值（差异租户优先取左侧首次出现值）、首个差异、`"different"`/`"missing_left"`/`"missing_right"`（缺失侧为 null、存在侧附原始记录）以及完全相等时 `{"ok": true, "equal": true, "tenants": [...]}` 摘要（左侧首次出现顺序、再接右侧独有租户）的全部确定语义，只报告唯一一个位置。该入口严格只读：绝不创建、改写或删除任一路径，不写清单、缓存或其他旁路数据，也不访问网络；文件内容损坏只返回上述校验结果而绝不改写日志。现有 append、批量追加、各类条件头追加、导入导出、读取、verify、heads、manifest、`compare_bytes` 和 `compare_chunks` 的签名、返回值、异常优先级、JSONL 字节格式及离线行为保持不变。

`manifest()`、`manifest_bytes(data)` 与 `manifest_chunks(chunks)` 生成**可随备份携带的本地快照清单**（version 1）：清单是一个对象，恰含 `version`、`byte_length`、`byte_sha256`、`tenants` 四个字段；`version` 固定为普通整数 `1`，`byte_length` 是快照的确切字节数，`byte_sha256` 是对快照**原始字节**计算的 64 小写十六进制 sha256（空字节摘要为 sha256 空输入值），`tenants` 按租户在快照中的**物理首次出现顺序**排列，每项恰含 `tenant`、`count`、`hash`——原始 tenant 值逐字保留、该租户已验证记录数、以及该租户**末条记录的 hash**（空链不列入）。空文件、空 bytes 或空拼接是合法空快照，返回空清单 `{"version": 1, "byte_length": 0, "byte_sha256": <sha256(b"")>, "tenants": []}`。三个入口都只读快照、不创建或修改日志、不写缓存或旁路元数据、不访问网络：`manifest()` 对文件取一次与 verify_all/heads/export_all 相同的只读共享锁完整快照（缺失文件视为空快照且不创建），`manifest_bytes(data)` 是纯内存入口（`data` 必须恰好是 `bytes`，`bytearray`/`str` 及其他类型在任何解码前统一 `ValueError`），`manifest_chunks(chunks)` 是分块入口，分块容器/成员边界与 `verify_all_chunks`/`heads_chunks` 完全一致（单个 `bytes`/`bytearray` 不算容器、不可迭代容器、首个非 `bytes` 成员立即停止消费；空块允许、可切在任意 UTF-8/JSON/LF 位置），对相同拼接字节与 `manifest_bytes` 的结果**逐字段相等**。生成清单前先以与 `export_all`/`verify_all` 完全相同的规则（严格 UTF-8、LF 唯一物理行界、标准 JSON、租户身份、每租户 seq/prev/hash）校验**完整快照**：发现任何损坏绝不返回部分清单，改抛 `AuditChainStateError`，`tenant`、`seq`、`reason`、`line` 字段与 export_all/verify_all 入口一致（reason 仅 missing、sequence、digest；不可解析行 tenant/seq 为 None）；三个入口对同一损坏给出相同字段。

`export_snapshot()` 与 `export_snapshot_chunks(chunk_size)` 是**原子快照导出**入口：分别调用 `export_all()` 与 `manifest()` 会让备份字节和清单来自两个不同的并发窗口，这两个入口把二者固定到**同一次完整快照**上。`export_snapshot()` 返回恰含 `data` 与 `manifest` 两键的只读结果：`data` 是该快照的原始 JSONL 字节（与同一快照上 `export_all()` 的返回值逐字节一致——租户交错顺序、换行与每个原始字节都逐字保留，绝不重排租户、改写换行或重新序列化），`manifest` 是由这份 `data` 直接算出的 version 1 清单，`byte_length` 与 `byte_sha256` 和 `data` 逐字节对应，`tenants` 的顺序、各租户 `count` 与末条 `hash` 都与该快照一致；并发追加只能整体落在这对结果之前或之后。`export_snapshot_chunks(chunk_size)` 面向大历史，返回恰含 `manifest` 与 `chunks` 两键的结果：`chunks` 是一次性 `bytes` 迭代器，只按字节偏移切分（可切在任意 UTF-8 序列、JSON 对象或换行中间），按序拼接后与同一快照上 `export_snapshot()` 的 `data` **逐字节相等**，空快照产出零个分块；`chunk_size` 沿用既有边界——必须是大于零的普通整数（`bool` 即使是 int 子类也拒绝，浮点、字符串、零、负数及其他类型一律 `ValueError`），且在读取任何历史之前检查。两个入口都在同一次只读共享锁快照上先完成与 `export_all` 完全相同的全链校验再产生任何结果：物理行无法按严格 UTF-8 和标准 JSON 解析、含重复键或非标准数字、缺字段、顺序错误、前摘要或当前摘要不匹配时，不返回部分结果（分块入口不产出任何分块），统一抛 `AuditChainStateError`，`tenant`、`seq`、`reason`、`line` 与 `export_all` 对同一物理首错的定位完全一致（reason 仅 missing、sequence、digest）。日志不存在或为空是合法空快照：`data` 为 `b""`、清单为现有空日志的 version 1 结果、零个分块。两个入口严格只读：不创建、替换或修改日志与任何旁路文件，不访问网络；`data` 或拼接后的分块可直接交给 `verify_all_bytes`、`heads_bytes`、`manifest_bytes`、`compare_bytes` 及离线导入入口，结果与对同一快照调用一致。现有 append、import/export、verify、heads、manifest、compact 和 compare 的行为不变。

`verify_manifest(manifest)`、`verify_manifest_bytes(data, manifest)` 与 `verify_manifest_chunks(chunks, manifest)` 用携带的清单校验目标日志快照：文件入口只取一次共享锁只读快照，字节与分块入口沿用 `verify_heads_bytes`/`verify_heads_chunks` 的类型边界与"绝不触碰构造器路径"语义——`verify_manifest_bytes` 的 `data` 必须恰好是 `bytes`，`verify_manifest_chunks` 的分块容器/成员规则与 `verify_all_chunks`/`heads_chunks` 相同且先校验清单再消费分块（非法清单一个分块都不会拉取），均不访问网络、不写缓存或落盘索引、不修改入参。**清单输入在读取任何历史之前验证为 version 1 对象**：顶层必须恰含 `version`、`byte_length`、`byte_sha256`、`tenants` 四键；`version` 必须是普通整数 `1`（`bool` 即使是 int 子类也拒绝，浮点、字符串、`None`、其他整数及其他类型一律 `ValueError`），`byte_length` 是非负普通整数（bool、负数、浮点、字符串、`None` 拒绝），`byte_sha256` 恰好 64 个小写十六进制字符（长度不符、大写、非 hex、非字符串拒绝），`tenants` 必须是列表，每项恰为含 `tenant`、`count`、`hash` 三键的对象：tenant 越过与 append/verify 相同的标准 JSON 边界（NaN/Infinity、非字符串键、循环容器等拒绝），count 为非负普通整数（bool 拒绝），hash 恰好 64 小写十六进制字符，且同一规范 JSON 租户身份在整个清单中至多出现一次（仅对象键顺序不同但身份相同同样 `ValueError`；`1`、`1.0`、`true`、`"1"` 互不相干）。任何形状、字段集合、长度、摘要格式、租户项结构或唯一性不合规都在读取快照/探测路径/解析任何字节**之前**统一抛 `ValueError`（不泄漏底层解析异常），并严格优先于损坏快照判定与清单比较。边界通过后，先执行现有完整链校验（严格 UTF-8、LF 或 CRLF 行界、标准 JSON、租户身份、seq、prev、hash 规则）：**链损坏优先**，首次损坏返回与 `verify_all` **逐字段一致**的失败对象 `{"ok": false, "at", "tenant", "reason"}`，reason 只允许 missing、sequence、digest，不进行任何清单比较、不返回部分结果。链完整后才按**固定的首次差异顺序**比较清单：先 `byte_length`，再 `byte_sha256`（均只需 expected/actual，无定位字段）；再 `tenant_order`——清单租户顺序必须与快照物理首次出现顺序（按规范 JSON 身份）逐项一致，含长度，首个不同位置（缺失/多余租户同样在此发现）返回 `"index"` 定位及该位置两侧的 tenant 值（缺侧为 null）；顺序一致后，按清单顺序先逐租户比较 `count`（`field="tenant_count"`，附 `tenant` 与 expected/actual），再逐租户比较末条 `hash`（`field="tenant_hash"`，同样附 `tenant` 与 expected/actual）。任何不一致都返回 `{"ok": false, "reason": "manifest", "field", ...}`：`field` 只能是 `byte_length`、`byte_sha256`、`tenant_order`、`tenant_count`、`tenant_hash` 之一，只附必要的 `index`（tenant_order）或 `tenant`（tenant_count/tenant_hash）以及 `expected`、`actual`，只报告按固定顺序确定的**唯一一个**首次差异，绝不连锁报告。全部一致返回 `{"ok": true, "manifest": <实际清单>}`，回显的是从快照实际算出的清单（含实际 byte_length、byte_sha256 与租户目录）而非入参对象；空快照与空清单匹配即如此。旧日志无需清单继续可用，清单仅在显式传入时校验；现有 append 系列、verify、heads、JSONL 导入导出及 compare 的返回值、优先级、JSONL 字段和摘要算法保持不变。

`verify_stream(chunks, tenant, expected_count=None)`、`verify_all_stream(chunks)`、`heads_stream(chunks)` 与 `manifest_stream(chunks)` 是**单次消费的流式离线校验**入口：JSONL 历史以按文件顺序给出的 `bytes` 可迭代对象到达，入口逐块增量校验，调用方无需先把整段拼成一个 bytes；空块允许，块可切在任意字节边界（UTF-8 序列、JSON 对象、LF/CRLF 行界中间），只有按序拼接的整段被解析，因此切入位置不改变任何语义。迭代器只向前消费一次，入口不读写或探测构造器路径、不创建或修改任何文件、不联网、不写缓存或落盘索引，也不修改任何入参块；空可迭代或仅含空块按空历史处理（`verify_stream` 成功为 `{"ok": True, "count": 0}`，`verify_all_stream`/`heads_stream` 成功为 `{"ok": True, "tenants": []}`，`manifest_stream` 返回空 version 1 清单）。容器/成员边界在读取任何块之前确定且与既有 `*_chunks` 入口一致：单个 `bytes` 或 `bytearray` 不算容器（其迭代会产出整数，统一 `ValueError`），不可迭代容器、首个非 `bytes`（含 `bytearray`、`str` 及其他类型）成员同样 `ValueError` 并立即停止消费后续块；`verify_stream` 的 tenant 沿用与 append/verify 相同的标准 JSON 边界、expected_count 必须是 `None` 或非负普通整数（bool 拒绝），非法 tenant/count 在拉取第一个块之前抛 `ValueError`。边界通过后，流内逐物理行复用既有严格 UTF-8、LF 唯一行界（行尾 CR 随行保留）、标准 JSON（重复键、NaN/Infinity/-Infinity 及溢出数一律拒绝）、规范 JSON 租户身份、每租户自 seq=1/prev=ZERO 的 seq 连续性与 prev/hash 摘要链规则，跨行重建物理行，因此：`verify_stream` 对 tenant、expected_count、成功返回以及 missing/sequence/digest 失败（`at` 口径与 verify_bytes 完全一致：顺序/摘要/短缺为期望 seq，缺失类为物理行号）与 `verify_bytes` **逐字段一致**；`verify_all_stream`、`heads_stream` 分别与 `verify_all_bytes`、`heads_bytes` 一致，沿用物理行号与租户首次出现顺序（heads 结果附已验证末条 hash）。前三个入口一旦在已凑齐的物理行上发现解析、字段、顺序或摘要错误，**立即停止索取后续块**并返回 missing、sequence 或 digest 结果，绝不返回部分 tenants（无法确定租户的行 tenant 为 None；尚未凑齐行尾 LF 的坏字节会在拉到补齐该行的块后再定位，此后同样停止）；记录全部有效时才消费到迭代结束。`manifest_stream` 在整段输入通过与 `manifest_bytes` 完全相同的链校验后才返回 version 1 清单，`byte_length` 与 `byte_sha256` 按**原始拼接字节**计算，`tenants` 与 `manifest_bytes` 保持同样的物理首次出现顺序与 `tenant`/`count`/`hash` 字段；历史损坏不返回部分清单，改抛 `AuditChainStateError`，其 tenant、seq、reason、line 与 `manifest_bytes` 对相同拼接字节的结果一致（reason 仅限 missing、sequence、digest，无法确定租户的行 tenant/seq 为 None；不泄漏底层 `UnicodeDecodeError`/JSON 异常）。不增加远端锚定或附加落盘格式；append、条件追加、import/export、read、compare、manifest、verify/heads 及现有 chunks 入口的结果、异常字段、JSONL 字段和摘要算法保持不变。

`verify_manifest_stream(chunks, manifest)` 是 `verify_manifest_bytes`/`verify_manifest_chunks` 的**单次消费流式清单核对**入口：JSONL 快照以按文件顺序给出的 `bytes` 分块可迭代对象到达，接收方无需把整份快照物化成单个 bytes 即可完成清单核对。清单边界与 `verify_manifest` 完全一致，并在索取任何分块**之前**验证（与 `verify_manifest_chunks` 同样先校验清单再消费分块）：非法结构、版本、长度、摘要、租户目录或重复规范 JSON 租户统一抛 `ValueError`，一个分块都不会拉取。分块容器/成员边界与 `verify_all_stream`/`manifest_stream` 完全一致：单个 `bytes` 或 `bytearray` 不算容器、不可迭代容器、首个非 `bytes`（含 `bytearray`、`str`）成员统一 `ValueError` 并立即停止消费；空块允许，分块可切在任意 UTF-8、JSON 或 LF 位置，迭代器只向前消费一次，迭代器自身抛出的异常原样透传。边界通过后，入口按**原始拼接字节**增量累计 `byte_length` 与 `byte_sha256`，并逐物理行增量执行与 `verify_all_bytes` 完全相同的严格 UTF-8、LF 唯一行界、标准 JSON（重复键与非标准数字拒绝）、字段集合、规范 JSON 租户身份、seq、prev、hash 规则：**链损坏优先**，首个确定的坏行立即停止索取后续分块，返回与 `verify_all_bytes` 逐字段一致的失败对象 `{"ok": false, "at", "tenant", "reason"}`（reason 仅 missing、sequence、digest，无法确定租户时 tenant 为 null），此时不比较任何清单字段。快照链完全有效后，才按 `verify_manifest_bytes` 的固定首次差异顺序比较从流中算出的清单：先 `byte_length`、再 `byte_sha256`、再 `tenant_order`（含长度，首个不同位置以 `index` 定位并附两侧 tenant 值，缺侧为 null）、再按清单顺序逐租户 `tenant_count`、最后逐租户 `tenant_hash`；任何不一致返回 `{"ok": false, "reason": "manifest", "field", ...}`（`field` 仅 `byte_length`/`byte_sha256`/`tenant_order`/`tenant_count`/`tenant_hash` 之一，只附必要的 `index` 或 `tenant` 定位与 `expected`/`actual`，只报告唯一一个首次差异）。全部一致返回 `{"ok": true, "manifest": <实际清单>}`，回显从流中实际算出的清单而非入参对象；空流与空清单匹配即如此。对相同拼接字节，本入口的结果与 `verify_manifest_bytes`、`verify_manifest_chunks` **逐字段一致**。该入口只消费调用方数据：绝不读取、创建或修改构造器指向的 AuditChain 路径，不访问网络、不写缓存或落盘索引，也不修改任何分块对象；现有追加、导入导出、读取、校验、清单及并发行为保持不变。

`verify_tenant_range_bytes(data, tenant, start_seq, end_seq=None, expected_prev=None)` 与 `verify_tenant_range_chunks(chunks, tenant, start_seq, end_seq=None, expected_prev=None)` 是**只读的单租户区间离线校验**入口：从备份中截取的租户区间可以被当作脱离原文件的迁移片段，在完全不接触目标日志的情况下确认它接续的是哪个前序摘要——前序链头由调用方以 `expected_prev` 显式给出，而不是去探测任何 AuditChain 路径。两者都只消费调用方快照，绝不读取、创建或修改构造器指向的路径，不联网、不写缓存或落盘索引，也不修改传入字节或分块。**参数边界先于一切读取或消费**：`data` 只能是 `bytes`（`bytearray`、`str` 及其他类型在任何解析前一律 `ValueError`，不泄漏底层解码/解析异常）；tenant 遵循与 append/verify/export 完全相同的标准 JSON 身份边界（NaN/Infinity、非字符串键、循环容器及无标准 JSON 编码的值一律 `ValueError`，`1`、`1.0`、`true`、`"1"` 仍是互不相干的租户）；`start_seq` 必须是正的普通整数（`bool` 即使是 int 子类也拒绝，`0`、负数、浮点、字符串及其他类型一律 `ValueError`）；`end_seq` 必须是 `None`（开放尾区间）或不小于 `start_seq` 的普通整数；`expected_prev` 必须恰好是 64 个小写十六进制摘要，且 `start_seq` 为 1 时只接受现有 `ZERO`（链首片段只能接空前序）。所有形状/类型/格式错误统一为 `ValueError` 且严格优先于任何内容判定与外来租户判定，目标路径既不被探测也不被创建。分块入口的容器/成员边界与 `verify_all_chunks`/`heads_chunks` 完全一致：单个 `bytes`、`bytearray` 不能当作容器（其迭代会产出整数），不可迭代容器、首个非 `bytes`（含 `bytearray`、`str`）成员一律 `ValueError`；全部参数在取得迭代器、拉取任何分块**之前**完成校验，遇到首个坏成员立即停止消费后续分块。分块只按字节拼接，可切在任意 UTF-8 序列、JSON 对象或 LF 位置，空块允许，迭代器只向前消费一次、其自身异常原样透传；因此对相同拼接内容，`chunks` 入口与 `bytes` 入口的结果**逐字段一致**，切入位置不改变语义。边界通过后，区间按现有全部规则逐物理行校验：复用 LF 唯一物理行边界（行尾 CR 随 CRLF 行保留并被严格 JSON 接受）、严格 UTF-8、标准 JSON（重复键、NaN/Infinity/-Infinity 及溢出数等非标准数字一律拒绝）与规范租户身份；每条物理行都必须是该**唯一**声明租户的对象且**恰好**含 tenant、seq、event、prev、hash 五个现有字段（混入任何其他规范 JSON 身份租户违反单租户区间契约，统一 `ValueError`，按物理行首个决定与内容缺陷的优先级）；seq 必须从 `start_seq` 起连续递增，首条 `prev` 必须等于 `expected_prev`，每条当前 `hash` 按现有摘要算法重算。空片段、无法严格 UTF-8/JSON 解析的行、非对象/缺字段/多字段，以及声明了 `end_seq` 却提前结束（区间缺尾）统一返回 `reason` 为 `"missing"` 的失败对象，缺尾的 `at` 为首条缺失序号；seq 不等于期望值（含 `1.0`/`1e0`、bool、字符串等非整数拼写，以及给出 `end_seq` 时出现越过该序号的多余记录——闭区间必须**恰好**覆盖，提前结束或超长都不能成功）返回 `"sequence"`；prev 或当前 hash 不符返回 `"digest"`；失败对象统一为 `{"ok": false, "reason", "at", "tenant", "start_seq", "end_seq"}`（`end_seq` 按调用原值，开放尾为 `None`），其中不可解析行的 `at` 为物理行号，缺字段行在携带普通整数 seq 时取其自身 seq、否则取期望 seq，顺序/摘要错误取期望 seq。成功返回 `{"ok": true, "tenant", "start_seq", "end_seq", "count", "hash"}`：开放尾区间的 `end_seq` 闭合为实际末条序号，`hash` 为末条记录摘要，可直接用于随后的 `import_tenant_range` 头部断言（`expected_count=start_seq-1`、`expected_hash=expected_prev`，末条 `hash` 即导入后新链头）。首个确定错误（missing/sequence/digest 或外来租户）一旦在已凑齐的物理行上出现，分块入口立即停止拉取后续分块，绝不消费到错误之后。现有追加、条件追加、批量追加、导入导出、verify、heads、manifest、compare、分页读取及各分块/流式入口的签名、返回值、异常优先级与 JSONL 字节兼容性保持不变。

`verify_all_range_bytes(data, expected_heads)` 与 `verify_all_range_chunks(chunks, expected_heads)` 是**只读的多租户区间纯离线校验**入口：多个租户交错的备份片段（通常由若干次 export_tenant_range 的记录按物理顺序拼成）可以在写入目标日志之前，仅凭调用方数据确认每个租户都从指定链头连续接上，而完全不接触任何 AuditChain 路径。两者都只消费调用方给出的字节或分块，绝不读取、创建或修改构造器指向的路径，不联网、不写缓存或旁车文件，也不修改入参。`expected_heads` 是按规范 JSON 租户身份（`json.dumps(..., sort_keys=True)`，对象键序不影响身份，`1`、`1.0`、`true`、`"1"` 互不相干）去重的有序列表，列表顺序即成功结果与冲突优先级顺序；每项必须是**恰好**含 `tenant`、`expected_count`、`expected_hash` 三个键的对象（参数不是列表、成员不是对象、缺键、多键或键集合不符一律 `ValueError`；非字符串成员键同样拒绝）：tenant 沿用与 append/verify/export 完全相同的标准 JSON 边界（NaN/Infinity、非字符串键、循环容器及无标准 JSON 编码的值一律 `ValueError`），`expected_count` 必须是非负普通整数（`bool` 即使是 int 子类也拒绝，负数、浮点、字符串、`None` 及其他类型一律 `ValueError`），`expected_hash` 必须恰好是 64 个小写十六进制字符（空链用现有 `ZERO`），同一规范 JSON 租户身份在整个列表中至多出现一次（仅对象键顺序不同同样 `ValueError`）。这些形状、字段、租户/计数/摘要格式与唯一性错误都在读取或解析任何字节、拉取任何分块**之前**统一抛 `ValueError`，不泄漏底层异常；`data` 不是恰好 `bytes`（含 `bytearray`、`str`）同样在解析前抛 `ValueError`。分块入口的容器/成员边界与 `verify_all_chunks`/`heads_chunks` 完全一致：单个 `bytes`、`bytearray` 不能当作容器（其迭代产出整数），不可迭代容器、首个非 `bytes`（含 `bytearray`、`str`）成员一律 `ValueError`，`expected_heads` 先于容器校验，遇首个坏成员立即停止消费；分块只按字节拼接，可切在任意 UTF-8 序列、JSON 对象或 LF 位置，空块允许，迭代器只向前消费一次、其自身异常原样透传，因此对相同拼接内容，`chunks` 入口与 `bytes` 入口的结果**逐字段一致**。边界通过后，片段按物理顺序逐行复用现有严格规则：LF 唯一物理行界（行尾 CR 随 CRLF 行保留并被严格 JSON 接受）、严格 UTF-8、标准 JSON（重复键、NaN/Infinity/-Infinity 及溢出数等非标准数字一律拒绝），每条物理行都必须是某个**已声明**租户的对象且**恰好**含 tenant、seq、event、prev、hash 五个现有字段；每租户从 `expected_count+1`、`expected_hash` 起序号连续，首条 prev 等于声明哈希，之后逐条引用，每条当前 hash 按现有摘要算法重算。空行、非对象、无法解析、非法 UTF-8、缺失或多余字段返回 `reason` 为 `"missing"` 的失败对象；seq 不等于下一期望值（含 `1.0`/`1e0`、bool、字符串等非整数拼写）为 `"sequence"`；prev 或当前 hash 不符为 `"digest"`；失败对象固定恰含 `{"ok": false, "at", "tenant", "seq", "reason"}` 五个字段，`at` 为物理行号，`seq` 为该租户该位置的期望序号（缺字段行携带普通整数 seq 时取其自身 seq），无法确定的租户或序号一律为 `null`——不可解析行的 `at` 仍是物理行号、`tenant`/`seq` 为 `null`；按输入物理顺序定位首个错误。出现未列入 `expected_heads` 的其他规范 JSON 身份租户违反片段契约，按物理行首个决定优先级统一抛 `ValueError`（与 import_all_range 的外来租户规则一致）。非空片段缺少某个已声明租户的记录时，返回该租户首个应有序号（`expected_count+1`）的 `missing`，其 `at` 为 `null`；空片段（零物理行）是合法成功，返回各租户**未变化**的声明头部（count 即 expected_count、hash 即 expected_hash）。成功返回 `{"ok": true, "tenants": [...]}`，`tenants` **按 `expected_heads` 原顺序**排列（而非物理首次出现顺序），每项给出接收片段后的 `tenant`、`count`、末条 `hash`，可直接作为下一段的前序头（即下一次 `import_all_range`/本入口的 expected_heads）。首个确定错误（missing/sequence/digest 或未声明租户）一旦在已凑齐的物理行上出现，分块入口立即停止拉取后续分块，绝不消费到错误之后。该入口是纯离线操作：不读取、不创建、不修改构造器路径，不访问网络，也不写任何旁车文件；append、条件追加、import_all_range、单租户区间校验、verify、heads、manifest、compare、既有 JSONL 字段、摘要算法、租户身份与异常行为保持不变，其结果可被现有离线迁移流程继续使用。

`compact()` 是**整份日志的离线压缩**入口：在不改变任何租户链含义的前提下消除历史 JSONL 的格式冗余（CRLF 行尾、末行缺换行、非规范键序、多余空白、非规范数字拼写），不接收任何业务事件参数。整条"读取一致快照—校验—替换"在一次排他租约内完成：目录租约先覆盖存在性探测（日志尚不存在是合法空历史，返回空 version 1 清单且**不创建文件**；已存在的空文件同样返回空清单、不改动任何字节），随后数据文件排他租约覆盖快照读取、全量校验与就地替换，加锁顺序始终是目录锁先于文件锁，与普通 append 不会死锁；并发追加、读取与校验只能观察到压缩前或压缩后的完整快照，绝不会看到改写到一半的文件。生成新快照之前，整份历史先按与 `export_all` 完全相同的严格规则校验——严格 UTF-8、LF 唯一物理行界（允许 CRLF 行尾）、标准 JSON（重复键、NaN/Infinity/-Infinity 及溢出数一律拒绝）、规范 JSON 租户身份、每租户从 `seq=1`、`prev=ZERO` 起的顺序与摘要链——并叠加 `import_all` 的恰字段契约：每条记录必须**恰好**含 tenant、seq、event、prev、hash 五个字段（多出的字段无法经规范化重序列化保留，同样按 missing 处理）。无法解析的行、缺字段或多字段、非法数字或非法 UTF-8 抛 `AuditChainStateError`，首次错误归类为 missing、sequence 或 digest，`tenant`、`seq`、`line` 的填充规则与 `verify_all`/`export_all` 完全一致（无法确定租户的行 tenant/seq 为 None）；任何错误都不改动原文件、不留下部分替换。只有整份历史有效后才生成新 JSONL 快照：每条记录按物理交错顺序原样保留五个字段的值，以追加入口的序列化（`sort_keys=True`、`allow_nan=False`）重写并以单个 LF 结尾，随后在租约内就地替换当前文件；已是规范形式的快照逐字节不变且不产生写入。成功时返回压缩后快照对应的 version 1 清单：字段集合与租户首次出现顺序沿用现有 `manifest()`，`byte_length` 与 `byte_sha256` 针对新快照字节计算，各租户计数与末条摘要与压缩前完全一致。重复压缩是幂等的：记录摘要、租户头部、manifest 租户目录与所有既有入口行为保持不变。压缩不引入旁车索引、临时文件、缓存、网络调用或远端锚定；现有 append、append_batch、条件追加、import/export、verify、heads、manifest 及其流式和字节入口的签名、返回值、错误字段与 JSONL 兼容性继续保持不变。

并发落盘的锁实现是**跨平台**的：同一路径可被 Windows 与 POSIX 上的 Python 进程共同安全使用。POSIX 上使用 `fcntl.flock`（数据文件描述符上的排他/共享整文件锁，目录本身的描述符承载目录租约）；Windows 上退化为 `msvcrt` 字节范围锁（以文件偏移 0 处的一个字节代表整文件咨询锁，共享租约以排他方式取得，语义等价、仅并发度更低），目录租约则由按目录路径派生命名的内核互斥体提供等价的互斥。两种后端都只使用标准库，不引入第三方依赖或服务，不写入锁文件、索引或任何旁路数据；模块导入与 `AuditChain` 构造不因平台缺少某个锁模块（`fcntl` 或 `msvcrt`）而失败，纯内存离线入口（`verify_bytes`、`verify_all_bytes`、`heads_bytes`、`manifest_bytes`、`compare_bytes`、各 `*_stream` 入口等）从不取锁，行为不受锁后端影响。写入、条件头比较、读取快照、校验、导入导出与压缩所需的锁无法取得、锁初始化失败或运行平台不支持所需锁语义时，相关操作统一抛出 `AuditChainLockError`：公开 `operation`（需要该租约的公开入口名）、`path`（目标日志路径）与固定 `reason` 值 `"lock"`，且不追加、不截断、不替换、不返回部分数据；锁在正常与异常退出后都必然释放（释放失败绝不掩盖操作自身的结果），不会留下阻塞后续调用的状态。锁错误与既有异常的优先级不变：参数非法仍在访问历史与加锁之前抛 `ValueError`，历史损坏仍抛 `AuditChainStateError`，头部断言不符仍抛 `AuditChainConflictError`；缺失日志的空历史语义（只读入口不需要锁即返回空历史）保持不变，同一目录下多个日志实例、多线程与多进程竞争以及压缩期间的读写行为与既有语义完全一致。
